[[hmac-test-plan]]
===== Test Plan

====== Standalone bench

`hmac_test` (`test/inc/hmac_test.h`) is a TLM initiator into the
register aperture, a second initiator into `keymgr_tl_socket`, plus
`clk_i` / `rst_ni` and helpers for CFG, CMD, MSG_FIFO, and digest
reads. The DUT is `hmac_ip`.

Success: every `assert_equal` / check in the standalone cases passes;
`--asan` produces no `asan.log.*`; line coverage on the touched model
sources meets the repository ≥ 95% gate.

How to run (from `sep/peripherals/hmac`):

[source,bash]
----
./run_tests.sh              # Release build + run
./run_tests.sh --debug
./run_tests.sh --asan       # ASan + UBSan
./run_tests.sh --coverage   # isolated build/coverage; do not combine with --asan
./run_tests.sh --ctest
./run_tests.sh --clean

# All SEP peripherals, this IP included:
cd sep/peripherals
./run_all_peripherals.sh
./run_all_peripherals.sh --clean hmac
----

`run_tests.sh` loads `SYSTEMC_HOME` / `CCI_HOME` through
`sep/peripherals/setup_build_env.sh`. Set those in `vp/configure_vp.sh`
or export them first.

====== Standalone cases

Sources: `test/src/basic_tests.cpp` (orchestration in
`test/src/testbench.cpp`). Names are the `test_*` methods.

[cols="12%,28%,44%,16%",options="header"]
|===
|ID |Name |What the model test proves |Type
|1–5 |Register access / reset |RO/WO/RW, reserved, reset |Positive
|6–9, 15 |SHA-2 hash |Digest vs OpenSSL, empty and multi-block |Positive
|10–14 |HMAC with configured keys |HMAC vs OpenSSL |Positive
|16–19 |Endian and packer |Message / digest / key swap, subword FIFO |Positive
|20–21 |FIFO and length |STATUS depth, MSG_LENGTH tracking |Positive
|22–25 |Interrupts |done / fifo_empty / err, mask, INTR_TEST |Mixed
|26–31 |Errors and protection |ERR_CODE, CFG/DIGEST lock, WIPE_SECRET |Mixed
|32 |Reset during processing |Abort to IDLE |Positive
|KM |Sideload |Socket, XOR shares, ignore SW key |Positive
|===

====== Platform firmware tests

These run on `sep-vp` with a RISC-V bare-metal toolchain. Build the VP
first (`make sep-vp` from the repo root after `vp/configure_vp.sh`).

Native suite (`sw/sep-vp-tests`):

[source,bash]
----
cd sw/sep-vp-tests
./run_sep_vp_tests.sh sep-hmac-test
./run_sep_vp_tests.sh hmac-dv-test
./run_sep_vp_tests.sh opentitan-hmac-test
----

Hardware-tree firmware:

[source,bash]
----
cd sw/sep-vp-tests/fw-tests-from-tt-oca-hw/fw/sep
./run_test.sh hmac_reg_sanity_test
./run_test.sh hmac_test
./run_test.sh hmac_hmac_mode_sha256_test
./run_test.sh hmac_interrupt_test
./run_all_tests.sh            # full firmware suite, includes HMAC
----

`hmac_p2_sensreg_access_test` is listed as a VP model gap in the
firmware-suite README.
