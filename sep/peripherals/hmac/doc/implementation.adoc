[[hmac-implementation]]
===== SystemC/TLM-2.0 Implementation

`hmac_ip` is a loosely-timed TLM-2.0 model. Timing is wait-on-`clk_i`
cycle counts, not a cycle-accurate SHA-2 datapath. The register file
lives in `hmac_base` so a map change lands in one header. Hash and HMAC
work runs on `sha2_engine`, an in-model SHA-2 core; see
<<hmac-sha2-core>> for why it is not OpenSSL EVP.

[source,cpp]
----
class hmac_ip : public hmac_base
----

----
hmac_ip          engine threads, interrupts, KM sideload   (hmac.*)
  └─ hmac_base   csml_memory + software-visible words      (hmac_base.*)
       └─ hmac_register.h   RO/WO/RW types
sha2_engine      SHA-256/384/512 core, loadable state      (sha2_engine.*)
hmac_interface.h   unused abstract `hmac_if` (ports are native sc_in/sc_out)
----

====== Threads and sockets

Block absorb and digest finalize each have an `SC_THREAD` woken by their
own start event. Interrupt pins are driven from a dedicated method so
reset is not a second SystemC writer.

`sep-vp` binds the TLM register target at the TRM HMAC aperture, the
three interrupt pins plus fatal alert into the PIC / alert fabric, and
the key-manager destination socket.

[cols="32%,28%,40%",options="header"]
|===
|Port |Type |Platform bind
|`hmac_base` memory target |TLM 32-bit |`sep-vp` SimpleBus, HMAC window
|`keymgr_tl_socket` |TLM 32-bit target |KM HMAC key socket
|`clk_i` |`sc_in<double>` |Frequency in Hz (latency only)
|`rst_ni` |`sc_in<bool>` |Active-low; falling edge clears state
|`intr_hmac_done` |`sc_out<bool>` |SEP PIC done source
|`intr_fifo_empty` |`sc_out<bool>` |SEP PIC FIFO-empty source
|`intr_hmac_err` |`sc_out<bool>` |SEP PIC error source
|`alert_fatal_fault` |`sc_out<bool>` |Fatal alert
|===

CMD writes notify the matching engine thread. MSG_FIFO writes pack
strobed bytes into words and push the message FIFO. KEY writes fill
internal WO storage; sideload XOR-reconstructs the KM shares into that
storage. WIPE_SECRET overwrites key and digest. W1C / W1S interrupt
registers recompute the pins.

----
  TLM MMIO ──► hmac_base::memory ──► block_processing_thread
                                 └► digest_computation_thread
                                           │
                                           ▼
                                 sha2_engine (+ ipad/opad)
                                           │
  keymgr_tl_socket ──► XOR reconstruct ──► key_storage
                                           │
                      interrupt_update ──► intr_hmac_*
----

[[hmac-sha2-core]]
====== Why the SHA-2 core is in-model

`hash_continue` loads an arbitrary chaining state, which OpenSSL's
supported interface does not allow: EVP exposes no digest mid-state, and
`SHA256_CTX` / `SHA512_CTX` are deprecated in 3.x. `sha2_engine`
therefore holds the chaining variables and bit count as first-class
state, as the hardware does. HMAC layers ipad/opad on the same core.
OpenSSL remains the reference the digests are checked against.

====== CCI parameters

Knobs are `csml_param`. Block and finalize costs are compile-time cycle
constants, scaled by `clk_i`.

[cols="36%,20%,44%",options="header"]
|===
|Parameter |Default |Use
|`verbosity` |2 (Release: 1) |CSML log level
|===

====== Modeling gaps versus RTL

* No cycle-accurate SHA-2 rounds; `sha2_engine` computes a whole block at
  a time and the cost is charged as a `clk_i` delay.
* FIFO depth is a software-visible counter, not a hardware RAM model.
* `hmac_if` is not the bound port set; `sep-vp` uses the native pins.
* No EDN / `entropy_src` ports.
