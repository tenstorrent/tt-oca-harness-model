[[sep-reset-ctrl-test-plan]]
===== Test Plan

====== Standalone bench

`sep_reset_ctrl_testbench` (`test/src/sep_reset_ctrl_testbench.cpp`)
is a TLM initiator into SW_RESET_N plus `global_rst_ni` and the five
output pins.

Success: the harness cases and the two pin-level tests pass;
`--asan` produces no `asan.log.*`; line coverage on the touched model
sources meets the repository ≥ 95% gate.

How to run (from `sep/peripherals/sep_reset_ctrl`):

[source,bash]
----
./run_tests.sh              # Release build + run
./run_tests.sh --debug
./run_tests.sh --asan       # ASan + UBSan
./run_tests.sh --coverage   # isolated build/coverage; do not combine with --asan
./run_tests.sh --ctest
./run_tests.sh --clean

# All SEP peripherals, this IP included:
cd sep/peripherals
./run_all_peripherals.sh
./run_all_peripherals.sh --clean sep_reset_ctrl
----

`run_tests.sh` loads `SYSTEMC_HOME` / `CCI_HOME` through
`sep/peripherals/setup_build_env.sh`. Set those in `vp/configure_vp.sh`
or export them first.

====== Standalone cases

Sources: `test/src/sep_reset_ctrl_test.cpp`,
`sep_reset_ctrl_testbench.cpp`.

[cols="8%,36%,40%,16%",options="header"]
|===
|ID |Name |What the model test proves |Type
|1 |Reset values |Default SW_RESET_N (KM held, crypto released) |Positive
|2 |Register access |RW of the five bits |Positive
|3 |Output updates |Each bit drives the matching `rst_n` |Positive
|4 |Global reset behaviour |CSR returns to default |Positive
|5 |Pin-level reset |Outputs follow AND with `global_rst_ni` |Positive
|6 |Global override |Asserting `global_rst_ni` forces all outputs low |Positive
|===
