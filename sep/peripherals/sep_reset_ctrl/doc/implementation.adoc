[[sep-reset-ctrl-implementation]]
===== SystemC/TLM-2.0 Implementation

`sep_reset_ctrl_ip` is a loosely-timed TLM-2.0 model of the software
reset controller. One 64-bit word is regmodel storage that drives
per-IP `rst_n` outputs. There is no engine thread and no FIFO.

[source,cpp]
----
class sep_reset_ctrl_ip : public sep_reset_ctrl_base
----

----
sep_reset_ctrl_ip     SW_RESET_N → rst_n pins   (sep_reset_ctrl.*)
  └─ sep_reset_ctrl_base   regmodel::Memory + SW_RESET_N
       └─ sep_reset_ctrl_register.h
----

====== Threads and sockets

`SC_METHOD(update_rst_outputs)` fires on `sw_reset_changed_` after a
CSR write. If the caller is an `SC_THREAD` (the ISS), the notify is
deferred one delta so downstream reset methods see a falling edge in
the next delta. `SC_METHOD(reset_handler)` on `global_rst_ni` restores
the documented default so firmware writes do not survive a platform
reset.

`sep-vp` maps the TLM target at the TRM reset-ctrl window. Outputs
feed key-manager, OTBN, AES, HMAC, KMAC, the TRNG complex
(entropy_src / CSRNG / EDN), and Adams Bridge `rst_ni`.

[cols="32%,28%,40%",options="header"]
|===
|Port |Type |Platform bind
|`target_socket` |TLM 32-bit |`sep-vp` SimpleBus, reset-ctrl window
|`global_rst_ni` |`sc_in<bool>` |Platform reset
|`km_rst_ni` |`sc_out<bool>` |Key-manager `rst_ni` (starts asserted)
|`otbn_rst_n` |`sc_out<bool>` |OTBN `rst_ni`
|`aes_rst_ni` |`sc_out<bool>` |AES `rst_ni`
|`hmac_rst_ni` |`sc_out<bool>` |HMAC `rst_ni`
|`kmac_rst_ni` |`sc_out<bool>` |KMAC `rst_ni`
|`trng_rst_ni` |`sc_out<bool>` |entropy_src / CSRNG / EDN `rst_ni`
|`abr_rst_ni` |`sc_out<bool>` |Adams Bridge `rst_ni`
|===

AND of `global_rst_ni` and the matching SW_RESET_N bit. KM's bit
resets to 0 (held in reset); the crypto, TRNG, and ABR bits reset to 1.
`update_rst_outputs` reads those bits through SW_RESET_N's named
bitfields, so the wiring is checked against the register description
rather than a separate table of bit positions.

The SW_RESET_N register word is the model's only copy of the software
reset state — there is no separate shadow variable. Because the IP
registers its own write callback on that offset, it *replaces* the one
`regmodel::Reg` bound to `Reg::handle_write`, so `handle_sw_reset_n_write`
has to store the masked value into SW_RESET_N itself; otherwise reads and
subsequent byte-enable merges would combine against the stale power-on
value. Byte-lane merging goes through `regmodel::apply_byte_enable` rather
than hand-rolled mask arithmetic, and `reset()` relies on
`reset_all_registers()` alone instead of restating the 0x7e default.

----
  TLM MMIO ──► SW_RESET_N write ──► sw_reset_changed_
  global_rst_ni ──► reset_handler
                         │
                         ▼
                  update_rst_outputs ──► km/otbn/aes/hmac/kmac/trng/abr rst_n
----

====== Modeling gaps versus RTL

* No isolate/drain before asserting a domain reset (RTL
  `sep_isolate_rst_seq`). An access while an IP is held still reaches
  the model.
* No reset stretcher or synchronizer; the pin is a boolean.
