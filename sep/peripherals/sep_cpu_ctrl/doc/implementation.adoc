[[sep-cpu-ctrl-implementation]]
===== SystemC/TLM-2.0 Implementation

`sep_cpu_ctrl_ip` is a loosely-timed TLM-2.0 model of the SEP system
CSR block. Most words are plain regmodel storage. A handful have
callbacks: NMI vector + lock, TRNG source + lock, timeout clear /
status, straps, fuse-sense, version, and the inbound window.

[source,cpp]
----
class sep_cpu_ctrl_ip : public sep_cpu_ctrl_base
----

----
sep_cpu_ctrl_ip     callbacks, hwif_in, window exports   (sep_cpu_ctrl.*)
  └─ sep_cpu_ctrl_base   regmodel::Memory + software-visible words
       └─ sep_cpu_ctrl_register.h
----

====== Threads and sockets

`SC_METHOD(reset_handler)` on `rst_ni`. `SC_METHOD(publish_window_process)`
is the sole driver of `sep_global_base_addr_o` / `sep_region_size_o`;
CSR writes and `publish_inbound_window()` notify it so SystemC sees
one writer. There is no engine thread.

`sep-vp` maps the TLM target at the TRM CPU-ctrl window, binds
`rst_ni` and the two window exports, and sets fuse-sense in `hwif_in`
before `sc_start` so boot is not blocked. Adapters read
`SEP_LOCAL_BASE_ADDR` / `SEP_REGION_SIZE` and
`SMU_GLOBAL_BASE_ADDR` / `SMU_REGION_SIZE` live.

[cols="32%,28%,40%",options="header"]
|===
|Port |Type |Platform bind
|`target_socket` |TLM 32-bit |`sep-vp` SimpleBus, CPU-ctrl window
|`rst_ni` |`sc_in<bool>` |Platform reset
|`nmi_vec_o` |`sc_out<uint32_t>` |NMI vector (`addr << 1`)
|`sep_global_base_addr_o` |`sc_out<uint64_t>` |Inbound window base [55:0]
|`sep_region_size_o` |`sc_out<uint64_t>` |Inbound window size [31:0]
|===

`REFERENCE_COUNTER` increments on each CSR read (not a free-running
clock). `TIMEOUT_INTERRUPT` / `TIMEOUT_CLEAR` only touch
`hwif_in.*_timeout_int`; nothing in the VP currently asserts those
flags.

----
  TLM MMIO ──► sep_cpu_ctrl_base::memory
  CSR window write ──► publish_window_process ──► sep_global_base_addr_o /
                                                   sep_region_size_o
  hwif_in / CCI straps ──► fuse-sense, TEST_CTRL, STRAPS reads
----

====== CCI parameters

Straps and fuse flags are snapshotted into `hwif_in` at
`end_of_elaboration`. Platform code may still overwrite `hwif_in`
before `sc_start`.

[cols="36%,20%,44%",options="header"]
|===
|Parameter |Default |Use
|`smc_fuse_sense_done` |0 |SMC fuse-sense status
|`sep_fuse_sense_done` |0 |SEP fuse-sense status
|`sep_standalone` |0 |TEST_CTRL.sep_standalone
|`fast_spi_en` |0 |TEST_CTRL fast-SPI
|`fast_iccm_en` |0 |TEST_CTRL fast-ICCM
|`fast_dccm_en` |0 |TEST_CTRL fast-DCCM
|`fast_sram_en` |0 |TEST_CTRL fast-SRAM
|`fast_pka_en` |0 |TEST_CTRL fast-PKA
|`test_en` |0 |STRAPS.test_en
|`bypass_mem_repair` |0 |STRAPS.bypass_mem_repair
|===

====== Modeling gaps versus RTL

* No timeout counters or expiry. `TIMEOUT_COUNT_*` / `TIMEOUT_ENABLE`
  / `TIMEOUT_MODE` are storage only.
* `CLOCK_GATE_CTRL` does not gate clocks.
* `KM_WIPE_CTRL` has no key-manager wipe consumer.
* `REFERENCE_COUNTER` is read-tick, not a cycle counter.
* Alias / output-remap / filter CSRs are other models, not this
  register file.
