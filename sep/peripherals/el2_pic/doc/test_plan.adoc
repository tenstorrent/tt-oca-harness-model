[[el2-pic-test-plan]]
===== Test Plan

====== Standalone bench

`testbench` (`test/inc/testbench.h`) is a TLM initiator into the PIC
MMIO, a `mock_hart` that records claim-id and EIP, plus `clk_i` /
`rst_ni` and a full `irq_in` vector. A second DUT is left with most
`irq_in` unbound to prove the tie-low path.

Success: every `report_test_pass` in the suite holds; `--asan`
produces no `asan.log.*`; line coverage on the touched model sources
meets the repository ≥ 95% gate.

How to run (from `sep/peripherals/el2_pic`):

[source,bash]
----
./run_tests.sh              # Release build + run
./run_tests.sh --debug
./run_tests.sh --asan       # ASan + UBSan
./run_tests.sh --coverage   # isolated build/coverage; do not combine with --asan
./run_tests.sh --ctest
./run_tests.sh --clean

# All SEP peripherals, this IP included:
cd sep/peripherals
./run_all_peripherals.sh
./run_all_peripherals.sh --clean el2_pic
----

`run_tests.sh` loads `SYSTEMC_HOME` / `CCI_HOME` through
`sep/peripherals/setup_build_env.sh`. Set those in `vp/configure_vp.sh`
or export them first.

====== Known gaps

`PIC-I-01` of the audit plan — the threshold sweep driven through the
production VeeR post-CSR callback rather than through
`notify_threshold_changed()` — is not covered. The test model compiles
the real `src/el2_pic.cpp` against `test/inc/VeeR-ISSTlm.hpp`
(`CMakeLists.txt:144-193`), so no real ISS CSR write path is linked in
and there is nothing to drive. Closing it needs a fixture that links the
production wrapper, not another standalone case. 024 covers the PIC-side
arithmetic the callback would exercise.

`transport_dbg` in `common/include/reg_file.h` shares
`read_registers()` / `write_registers()` with `b_transport`, so a debug
*write* runs post-write side effects. 027 asserts that as the current
policy rather than the stricter side-effect-free reading of TLM-2.0; it
is shared-infrastructure behaviour, not PIC behaviour.

====== Platform firmware tests

The PIC is inside the hart. Any `sep-vp` test that takes an external
IRQ exercises it. Build the VP first (`make sep-vp` from the repo
root after `vp/configure_vp.sh`).

[source,bash]
----
cd sw/sep-vp-tests/fw-tests-from-tt-oca-hw/fw/sep
./run_test.sh sep_mailbox_plic_test
./run_test.sh otbn_plic_test
./run_test.sh spi_ot_interrupt_test
./run_all_tests.sh            # full firmware suite
----
