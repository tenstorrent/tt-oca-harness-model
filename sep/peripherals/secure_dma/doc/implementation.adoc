[[secure-dma-implementation]]
===== SystemC/TLM-2.0 Implementation

`secure_dma_model` is a loosely-timed TLM-2.0 model that follows the
control state machine of `secure_dma.sv`. Each beat is a blocking
read-then-write pair on the ASID-selected initiator socket; a zero fill
(opcode `0x4`) issues the writes only, each checked against
`ENABLED_MEMORY_RANGE`. Every beat is a word-aligned 4-byte transaction
with the RTL's byte enables, and a sub-word read is steered to every
byte lane. SHA-2 is OpenSSL. Time advances by the targets' annotated
delays.

[source,cpp]
----
class secure_dma_model : public secure_dma_base
----

----
secure_dma_model     engine, SHA-2, handshake, IRQ   (secure_dma.*)
  └─ secure_dma_base regmodel::Memory + target_socket     (secure_dma_base.*)
----

====== Threads and sockets

`engine_thread` is the state machine. In `DmaIdle` it waits for
`CONTROL.go`, or for a set busy flag between handshake chunks, and in
handshake mode for an enabled `lsio_trigger` to be high. It then sets
up and moves one beat at a time and returns to idle at every chunk
boundary. An error parks it in `DmaError` until software clears
`STATUS.error`; `CONTROL.abort` returns it to idle from any state.
Outside a data move, a `CONTROL` or `STATUS` write takes effect inside
the write, so a read that follows sees the new state. `reset_thread`
clears state. `interrupt_driver_method` is the only writer of the three
interrupt pins, which are status type: `INTR_STATE` is `STATUS.{error,
chunk_done, done}` or'd with the last `INTR_TEST` write.

`sep-vp` binds the register target at the TRM DMA aperture. The OT
initiator reaches the SEP xbar through `dma_alias_remap_adapter`, which
applies the local-alias window, refuses a DMA write to ICCM or DCCM
that does not enable all four byte lanes, and reports any error
response as `DMA_BUS_ERR_STATUS.host_path_err` (IRQ 42). The CTN
initiator, and the 64-bit SYS initiator through `dma_sys_bus_adapter`,
end in dead-end stubs that answer with an error, where silicon ties the
ports off. SPI TX handshake drives `lsio_trigger[0]`. Done / chunk-done
/ error go to the PIC.

A memory-to-memory chunk ends with `go` and `busy` clear and
`STATUS.chunk_done` set; the next `go` continues the transfer, keeping
the byte count and beat addresses. Only a start with
`initial_transfer` takes the opcode and digest swap and restarts the
count, and hardware clears the bit. In handshake mode `go` arms
without setting `busy`; each chunk starts while an enabled trigger is
high, after the `CLEAR_INTR_SRC` writes in index order, and the final
chunk clears `go`.

ASID `0x7` / `0x9` / `0xA` select OT / SYS / CTN. Security policy
blocks OT-private ↔ SoC unless the transfer stages through the
enabled DMA range.

----
  TLM MMIO ──► CONTROL / STATUS ──► engine_thread ◄── lsio_trigger[]
                                  │
                    ot / ctn / sys initiator ──► memory
                                  │
                    OpenSSL SHA-2 ──► SHA2_DIGEST[]
                                  │
                    interrupt_driver_method ──► dma_*_intr
----

====== CCI parameters

Knobs are `regmodel::Param` and are re-read when used. Transfer rate
comes from the targets' annotated delays, not a cycle-count parameter.

|`verbosity` |2 (Release: 1) |regmodel log level
|===

====== Modeling gaps versus RTL

* No cycle-accurate bus protocol or SHA-2 datapath.
* Single channel; no burst packing.
* On `sep-vp` a handshake interrupt-clear write on the CTN bus
  (`CLEAR_INTR_BUS` bit clear) gets an error response and stops the
  transfer, where silicon would hang on the tied-off port.
* RACL on the system bus is not modelled as a separate port.
* One beat is outstanding at a time, and an abort takes effect at the
  next beat boundary rather than mid-transaction.
* Not suitable for performance measurement.
