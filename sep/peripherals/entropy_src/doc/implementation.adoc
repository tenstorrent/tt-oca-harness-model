[[entropy-src-implementation]]
===== SystemC/TLM-2.0 Implementation

`entropy_src_ip` is a loosely-timed TLM-2.0 model. Timing is a
programmable startup hold-off plus a downsample period, not a
cycle-accurate ring-oscillator pipeline. The register file lives in
`entropy_src_base` so a map change lands in one header. Entropy words
are OpenSSL `RAND_bytes()`, not a physical noise source.

[source,cpp]
----
class entropy_src_ip : public entropy_src_base, public entropy_src_if
----

----
entropy_src_ip          generation thread, FIFO, irq_o   (entropy_src.*)
  └─ entropy_src_base   regmodel::Memory + software-visible words
       └─ entropy_src_register.h   RO/WO/RW types
entropy_src_interface.h   register-callback contract
----

====== Threads and sockets

`entropy_generation_thread` fills the FIFO while enabled. Reset is an
`SC_METHOD` on `rst_ni`. Quantum-keeper pacing waits are interruptible
by `rst_ni` and `m_reset_event` so a TRNG-domain reset is not stuck
behind an in-flight timed wait. `irq_o` is driven from
`interrupt_output_method` so callbacks are not a second SystemC writer.

`sep-vp` binds the TLM register target at the TRM entropy-source
aperture, `rst_ni`, and `irq_o`. There is no `clk_i` pin. Its
`entropy_export` is bound to CSRNG and supplies 384-bit seeds by
destructively consuming 12 words from the modeled entropy FIFO.

[cols="32%,28%,40%",options="header"]
|===
|Port |Type |Platform bind
|`entropy_src_base` memory target |TLM 32-bit |`sep-vp` SimpleBus, ENTROPY_SOURCE window
|`rst_ni` |`sc_in<bool>` |Active-low; falling edge clears state
|`irq_o` |`sc_out<bool>` |SEP PIC (`INTR_STATUS & INTR_ENABLE`)
|`entropy_export` |`sc_export<entropy_provider_if>` |CSRNG 384-bit seed input
|===

rst_ni (TRNG SW_RESET_N bit) resets the model. FIFO_RDATA pops the queue
(underflow if empty). FIFO_CTRL gates the filler thread. Health-test
enable is captured; the running tests are a stub.

`STARTUP_CTRL` (offset `0xB0`, RW) holds the startup hold-off in
`DELAY_CYCLES[15:0]`; bits `[31:16]` are reserved RAZ/WI. The model caches
it in `m_startup_delay_ns`, and `reset_process()` re-derives that cache —
along with the FIFO and health-test enables — from the register values
restored by `reset_all_registers()`, so the CSRs stay the single source of
truth for every reset default.

`FIFO_CTRL.ENABLE` gates entropy *generation*, not draining: disabling the
FIFO stops the filler thread but leaves the queued words readable. Both the
software path (`FIFO_RDATA`) and the `entropy_export` seed path pop
regardless of the enable, so CSRNG and firmware see one FIFO with one set
of rules.

----
  TLM MMIO ──► entropy_src_base::memory
                         │
                         ▼
           entropy_generation_thread ──► m_fifo ──► FIFO_RDATA
                         │
           interrupt_output_method ──► irq_o
----

====== CCI parameters

Knobs are `regmodel::Param`. Startup delay and downsample come from CSRs, not
CCI.

[cols="36%,20%,44%",options="header"]
|===
|Parameter |Default |Use
|`verbosity` |2 (Release: 1) |regmodel log level
|===

====== Modeling gaps versus RTL

* No ring oscillators, decorrelator datapath, or conditioner.
* The production `entropy_export` pops 12 FIFO words per CSRNG seed. When
  the repetition test is enabled, those bytes are scored against the
  programmed repetition limit and update failure/interrupt state.
* The full adaptive-proportion and Markov tests remain register-visible
  abstractions; this is not a cycle-accurate conditioner.
* No `clk_i`; iteration period is a constant nanosecond scale.
* Firmware-visible health counters are not a NIST SP 800-90B lab.
