[[kmac-test-plan]]
===== Test Plan

====== Standalone bench

`kmac_test` (`test/inc/kmac_test.h`) is a TLM initiator into the
register aperture, a KM initiator into `keymgr_tl_socket`, app-interface
drivers on `app_export[]`, plus `clk_i` / `rst_ni` / `lc_escalate_en_i`.
The DUT is `kmac_ip`.

Success: every check in the FUNC-KMAC suites passes (229 cases); `--asan`
produces no `asan.log.*`; line coverage is 94.4%, just under the
repository ≥ 95% gate, the residue being OpenSSL failure branches and
`EnMasking = 0` paths.

How to run (from `sep/peripherals/kmac`):

[source,bash]
----
./run_tests.sh              # Release build + run
./run_tests.sh --debug
./run_tests.sh --asan       # ASan + UBSan
./run_tests.sh --coverage   # isolated build/coverage; do not combine with --asan
./run_tests.sh --ctest
./run_tests.sh --clean

# All SEP peripherals, this IP included:
cd sep/peripherals
./run_all_peripherals.sh
./run_all_peripherals.sh --clean kmac
----

`run_tests.sh` loads `SYSTEMC_HOME` / `CCI_HOME` through
`sep/peripherals/setup_build_env.sh`. Set those in `vp/configure_vp.sh`
or export them first.

====== Platform firmware tests

These run on `sep-vp` with a RISC-V bare-metal toolchain. Build the VP
first (`make sep-vp` from the repo root after `vp/configure_vp.sh`).

Native suite (`sw/sep-vp-tests`):

[source,bash]
----
cd sw/sep-vp-tests
./run_sep_vp_tests.sh sep-kmac-dv-test
----

Hardware-tree firmware:

[source,bash]
----
cd sw/sep-vp-tests/fw-tests-from-tt-oca-hw/fw/sep
./run_test.sh kmac_reg_sanity_test
./run_test.sh kmac_sha3_256_test
./run_test.sh kmac_shake128_test
./run_test.sh kmac_key_sideload_test
./run_all_tests.sh            # full firmware suite, includes KMAC
----
