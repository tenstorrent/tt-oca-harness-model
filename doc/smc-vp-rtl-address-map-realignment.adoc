[IMPORTANT]
====
This is a *review draft*, not an implementation plan that has been
approved. Do not start the remap until the source-of-truth statement
(<<sot>>), the open decisions in <<open-decisions>>, and the phase
split in <<phases>> have been signed off.
====

This document proposes realigning the SMC virtual-platform address map
(`smc-vp` / `smu-vp`) to the current RTL `smc_top` map. It records the
mismatches confirmed against `tt-oca-harness`, the proposed target map,
the files that would have to move together, and the questions reviewers
must answer before code changes start.

[[problem]]
== Problem

The VP peripheral map is multi-sourced and has drifted from RTL.
`vp/platform/smc/src/smc_platform.cpp` and
`sw/smc-vp-tests/common/smc_common.h` place several modeled IPs on the
wrong slot (or on a slot RTL assigns to a different owner). Comments
that cite "`smc_top.rdl`" are themselves stale — for example
"`system_timer_octs` @ `0xC000_E000` per `smc_top.rdl`" is false against
the current RDL, where OCTS is at `0xC000_A000`.

Firmware tests in `sw/smc-vp-tests/` are one ELF per IP. That is useful
for isolation, but it cannot catch "this window is the wrong owner"
because each test only touches the base it was written against.

There is no file named `smc_top.rdl` in the current harness tree. The
colleague review that used "`smc_top.rdl` — tt-oca-hw`" is referring to
the `addrmap smc_top` inside `smc.rdl`. That is the correct SoT.

Cross-check rule for this remap: a VP base is "RTL-aligned" only when
it matches *both* `smc.rdl` *and* the corresponding xbar package. If
those two ever disagree, stop and raise it; do not pick a third number.

[[not-sot]]
=== What is not source of truth

Do *not* copy bases from these. They describe an older map (OCTS at
`0xE000`, AVSBus at `0x8000`, UART at `0xA000`, GPIO at `0x4000`):

* VP comments in `smc_platform.cpp` and `smc_common.h`
  ("OCTS @ E000 per `smc_top.rdl`").
* `smc/cpu_cluster/doc/05_RTL_SystemC_Integration_Guide.md` §6.
* `smc/doc/systemc_tlm2_integration_guide.adoc` address-map table
  (mixed current and stale rows).
* Harness `hw/sys/smc/dv/docs/SMC_VPLAN.adoc` (AVSBus still at
  `0xC000_8000`, GPIO at `0xC000_4000`).
* Fabric comments claiming "`verbatim from smc_local_xbar_pkg.sv`"
  for PLIC at `0xC080_0000` — the RTL xbar has
  `FRONT_PORT_PLIC_BASE = 0xC4000000`.

[[scope]]
== Scope

In scope:

* SMC local-alias aperture decode in `smc-vp` / `smu-vp`
  (`smc_platform`, `smc_fabric`, FW headers, CCI presets).
* Moving already-modeled IPs onto their RTL bases (AVSBus, UART, OCTS,
  PLL, PVT, cpu_ctrl CSR window).
* Fabric window ends that disagree with the RTL xbar (`periph_main`,
  DFX, PLIC/CLINT/BEU).
* A cumulative firmware map-coherence test (see <<fw-coherence>>).
* Doc/comment cleanup so no remaining comment cites a stale RDL base
  as current.

Out of scope for this remap (track separately):

* New functional models for IPs that RTL has and VP does not
  (`gpio_intf`, `smc_efuse_map`, `efuse_interface_ctrl`, `dtp_ctrl`,
  `dfx_ctrl`, `misc_wrap`). After the remap those slots become stubs
  at the *correct* base; modeling them is follow-on work.
* Cycle-accurate UART log-engine, eFuse programming, or DFX behaviour.
* Changing PeakRDL / RTL. If a reviewer believes `smc.rdl` itself is
  wrong, that is an RTL ticket, not a VP remap.

[[uart-layout]]
=== RTL UART wrap layout (needed for the UART move)

`uart_wrap.rdl` places `uart_log_engine_wrap[MAX_NUM_UARTS=4] @ 0x0 += 0x400`
under `smc_uart_wrap @ 0xC000_6000` (window size `0x1000`).

Each instance:

[cols="14,22,30,34",options="header"]
|===
|Inst |Wrap base |16550 (`uart`) |Log engine

|0
|`0xC000_6000`
|`0xC000_6100`
|`0xC000_6200`

|1
|`0xC000_6400`
|`0xC000_6500`
|`0xC000_6600`

|2
|`0xC000_6800`
|`0xC000_6900`
|`0xC000_6A00`

|3
|`0xC000_6C00`
|`0xC000_6D00`
|`0xC000_6E00`
|===

VP today uses four independent 4 KiB windows at `0xC000_A000 + N×0x1000`
with the 16550 at offset 0. Realigning UART is therefore both a *base*
change and a *sub-decode* change: `SMC_UARTn_BASE` must become the 16550
base (`0xC000_6100 + N×0x400`), not the wrap base, or `printf` / `start.S`
will write the log-engine-ctrl word at `+0x00`.

[[open-decisions]]
== Open decisions (reviewers must pick)

[[decision-aou]]
=== D1 — Where do AOU CSRs live?

AOU is *not* in `smc_top`. Today's `0xC000_4000` placement was a VP
invention that collides with RTL AVSBus. SEP reaches the same CSRs at
`0x4000_4000` via the SMU window remap (`addr | 0xC000_0000`), so the
choice also moves `sw/smu-vp-tests/smu-aou-ext-test`.

Proposed options:

[cols="8,30,31,31",options="header"]
|===
|ID |Placement |Pros |Cons

|A
|Sim-only reserved gap in `smc_top` that RTL leaves unmapped:
`0xC000_C000`, window `0x80` (between `dfx_ctrl` end and
`smc_base_config`).
|No RTL collision. Still inside today's cluster MMIO
`[0xC000_0000, 0xC100_0000)`. Small FW/header churn.
|Invented slot. Must be labeled "VP-only, not in `smc_top`" everywhere.
`0xC000_C000` is also where UART2 lives today — must move UART first.

|B
|Inside `smc_external`, e.g. `0xC040_1000` (below PLL at `+0x2000`,
above the vendor eFuse-shim / GPIO-ctrl region).
|Keeps adopter-ish IP in the adopter window. No collision with
GPIO/AVSBus/UART/OCTS.
|Still invented. `smc_ip_integration.sv` does not decode this offset
(unmapped → DECERR in RTL). Firmware that later runs on RTL will
fault.

|C
|Do not map AOU CSRs on the SMC local aperture. Reach them only
through the SMU/D2D path (or a dedicated VP socket).
|Honest: AOU is not an `smc_top` block.
|Breaks `smc-aou-test` as a standalone `smc-vp` ELF unless the
platform grows a side-door. Larger change.

|D
|Ask RTL/architecture for an official `smc_top` (or `smc_external`)
slot, then use that.
|Single SoT going forward.
|Blocked on an RTL change. Phase 1 can still *vacate* `0xC000_4000`
and park AOU at option A until the official slot exists.
|===

*Recommendation for reviewers:* accept *D as the long-term answer*,
and *A as the Phase-1 parking slot* so AVSBus can move to
`0xC000_4000` without waiting on RTL. Reject leaving AOU at
`0xC000_4000`.

[[decision-plic]]
=== D2 — PLIC / CLINT / BEU: align now or later?

RTL places these *outside* the 16 MiB local-alias region
(`LOCAL_ALIAS_REGION_SIZE = 0x0100_0000` →
`[0xC000_0000, 0xC100_0000)`):

* PLIC `0xC400_0000` (64 MiB xbar window)
* CLINT `0xC800_0000`, BEU `0xC801_0000`

Today `cluster.mmio_lo/hi` is `0xC000_0000` / `0xC100_0000`, so a
firmware load of `0xC400_0000` never even enters the fabric as MMIO.

Options:

[cols="8,40,52",options="header"]
|===
|ID |Choice |Implication

|P1
|Phase 3: expand `cluster.mmio_hi` to at least `0xC802_0000`, move
fabric `FRONT_PLIC_*` / `FRONT_CLINT_BEU_*` to the RTL xbar values,
update `SMC_PLIC_BASE` / `SMC_CLINT_BASE` / `SMC_BEU_BASE`.
|Firmware-visible. Zephyr, BEU tests, AVSBus PLIC claim paths all
move. Correct vs RTL.

|P2
|Leave PLIC/CLINT/BEU at the current local-alias bases
(`0xC080_0000` / `0xC0C0_0000` / `0xC0C1_0000`) and document them as
a *known VP alias*, not as `smc_top`.
|Smaller Phase 1. Continues to occupy RTL `ecam_region` at
`0xC080_0000`. Comments that say "verbatim from the xbar pkg" must
be deleted either way.
|===

*Recommendation:* *P1 in Phase 3*, not in the same PR as the
peripheral shuffle. Phase 1 must not claim "the VP map matches RTL"
until Phase 3 lands.

[[decision-uart]]
=== D3 — UART 16550 offset

Options:

[cols="8,40,52",options="header"]
|===
|ID |Choice |Implication

|U1
|`SMC_UARTn_BASE` = 16550 base (`0xC000_6100 + N×0x400`). Wrap /
log-engine bases are separate macros if a log-engine model appears
later.
|`printf.c` / `start.S` keep using `BASE + UART_THR` as today.

|U2
|`SMC_UARTn_BASE` = wrap instance base (`0xC000_6000 + N×0x400`);
firmware adds `+0x100` for 16550.
|Closer to the RDL instance name. Every existing UART access site
must add the offset. Easier to get wrong.
|===

*Recommendation:* *U1*. The software-visible UART is the 16550.

[[decision-sot-headers]]
=== D4 — How does VP stop drifting again?

Options:

[cols="8,40,52",options="header"]
|===
|ID |Choice |Implication

|H1
|Keep hand-written `smc_common.h` / `smc_platform.cpp` constants, but
add `sw/smc-vp-tests/smc-map-coherence-test` that asserts the same
literals against a checked-in copy of generated `smc_addr.h` (or a
slim extracted table).
|Low ceremony. The cumulative test is the drift detector.

|H2
|Firmware includes a vendored snapshot of
`smc_top_regs.h` / `smc_addr.h`. Platform C++ includes a generated
C++ equivalent (or the same C header).
|One edit path. Requires a vendor/sync process when RTL RDL moves.

|H3
|Generator in this repo that emits both C and C++ from `smc.rdl`.
|Best long-term, largest up-front cost. Out of scope unless someone
owns the PeakRDL pipeline here.
|===

*Recommendation:* *H1 now*, *H2 when we next sync a harness drop*.
Do not block Phase 1 on a generator.

[[phases]]
== Proposed phases

Each phase is a reviewable PR. Do not combine Phase 1 and Phase 3.

[[phase-1]]
=== Phase 1 — Peripheral shuffle (inside today's 16 MiB MMIO)

Goal: every *already-modeled* peripheral that lives in
`[0xC000_2000, 0xC000_B800)` or `smc_external` sits at its RTL base.
AOU vacates `0xC000_4000`.

Work:

. Move AVSBus → `0xC000_4000`.
. Move OCTS → `0xC000_A000`.
. Move UART wrap → `0xC000_6000` with 16550 at `+0x100` (<<decision-uart>>).
. Move PLL → `0xC040_2000`, PVT → `0xC040_3000`.
. Drop the extra `cpu_ctrl` bind at `0xC040_0000`; firmware uses
  `SMC_CPU_CTRL_FP_BASE` (`0xC003_9000`) only.
. Park AOU at the agreed slot (<<decision-aou>>).
. Point named stubs at `gpio_intf` / eFuse / DTP / `misc_wrap` (optional
  but useful for the coherence test).
. Update `smc_common.h`, `printf.c` / `start.S` comments, CCI INI if
  any base is a preset, AOU / OCTS / AVSBus / PLL / PVT READMEs.
. Add `smc-map-coherence-test` (<<fw-coherence>>).
. Re-run every `sw/smc-vp-tests/` ELF and the SMU AOU ext test.

Not in Phase 1: PLIC/CLINT/BEU, fabric `periph_main` end, DFX window.

[[phase-2]]
=== Phase 2 — Fabric windows vs RTL xbar

Goal: `smc_fabric.h` decode matches `smc_local_xbar_pkg.sv` and
`smc_internal_axi_lite_xbar_pkg.sv` for the *non-PLIC* windows.

Work:

. `PERIPH_MAIN_END`: `0xC000_E800` → `0xC000_B800`.
. `DFT_CSR_*`: `0xC000_F800` → `0xC000_B800` (size `0x800`).
. `DACCEL_DMA_ZEROER_END`: `0xC003_A000` → `0xC003_9000`.
. Delete "verbatim from xbar pkg" comments that are still wrong
  (PLIC lines wait for Phase 3).
. Update `smc/smc_fabric/doc/01_overview_and_architecture.md` and
  `05_systemc_implementation.md`.
. Fabric unit tests (`smc_fabric_tb`) that hard-code the old ends.

[[phase-3]]
=== Phase 3 — Core-local PLIC / CLINT / BEU (if D2 = P1)

Goal: firmware-visible PLIC/CLINT/BEU bases match `smc_top` and
`FRONT_PORT_*` in `smc_local_xbar_pkg.sv`.

Work:

. `cluster.mmio_hi` (CCI default + INI) → at least `0xC802_0000`.
. Fabric `FRONT_PLIC_*` / `FRONT_CLINT_BEU_*` → RTL values.
. `SMC_PLIC_BASE` / `SMC_CLINT_BASE` / `SMC_BEU_BASE` + every FW
  test that claims/completes PLIC or pokes BEU.
. Zephyr `mmio_poke` / board DTS if those nodes exist.
. Confirm `ecam_region` at `0xC080_0000` is no longer swallowed by
  the PLIC window.

[[phase-4]]
=== Phase 4 — Doc hygiene

Goal: no remaining checked-in doc presents the old map as current.

`0xC000_8000`, `0xC080_0000` after Phases 1–3):

* `smc/doc/systemc_tlm2_integration_guide.adoc`

[[fw-coherence]]
== Firmware: keep per-IP smokes, add a map-coherence ELF

Today `sw/smc-vp-tests/` runs one ELF per IP. Keep that.

Add `smc-map-coherence-test` (Phase 1) as a single ELF that:

. Writes a distinctive token to each *modeled* window and reads it
  back (UART SCR, AVSBus a safe RW, OCTS a documented RW, telemetry
  a documented RW, AOU `ip_version`, PLL/PVT a documented RW).
. Reads a known RO reset value where one exists (AOU `ip_version`,
  AVSBus CFG reset, WDT, etc.).
. For each *stubbed* RTL slot (`gpio_intf`, eFuse, DTP, DFX),
  performs a read and checks the stub contract (RAZ, or a
  platform-defined stub ID if we add one) so the test fails if a
  modeled IP has drifted back onto that slot.
. Walks a table of `{name, base, kind}` compiled from the same
  literals as `smc_common.h`, so the test and the header cannot
  disagree.

This is the cheap substitute for "include generated `smc_addr.h`"
until D4/H2 exists.

[[risks]]
== Risks and non-goals

* *Silent dual-map.* If platform C++ moves and `smc_common.h` does
  not (or the reverse), every existing ELF goes green against the
  wrong silicon. Phase 1 must land those files in one PR.
* *UART sub-decode.* Moving the wrap base but leaving 16550 at
  offset 0 will look like a hung console (`printf` polling LSR at
  the log-engine-ctrl address). Treat U1/U2 as a hard prerequisite.
* *PLIC outside 16 MiB.* Phase 3 without expanding `mmio_hi` makes
  every interrupt test appear to "lose" the PLIC.
* *SEP/SMU AOU window.* `0x4000_4000` is `0x4000_0000 | 0x0000_4000`.
  Parking AOU at `0xC000_C000` implies SEP should use `0x4000_C000`
  if the remap is a simple OR/alias of the low bits. Confirm against
  `axi_window_remap` before changing `smu-aou-ext-test`.
* *Do not* invent a second `smc_top` in this repo. The remap copies
  RTL numbers; it does not become a new SoT.

== Review checklist

Please answer explicitly in review comments:

. [ ] Confirm `hw/sys/smc/regs/smc.rdl` `addrmap smc_top` is the SoT
      for VP bases (<<sot>>).
. [ ] D1 AOU placement: A / B / C / D (recommend A now, D later).
. [ ] D2 PLIC/CLINT/BEU: P1 (Phase 3) or P2 (document as VP alias).
. [ ] D3 UART macros: U1 (16550 base) or U2 (wrap base).
. [ ] D4 drift control: H1 / H2 / H3.

      docs) is acceptable; Phase 1 must not include Phase 3.
. [ ] Named stubs at unmodeled RTL slots are acceptable in Phase 1
      (no new gpio/eFuse/DTP/DFX models).
. [ ] `smc-map-coherence-test` is wanted in Phase 1.
