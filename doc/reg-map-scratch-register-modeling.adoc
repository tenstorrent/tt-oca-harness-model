= Modeling Scratch CSRs with `reg_map.h`
:doctype: article
:sectanchors:
:sectlinks:
:sectnums:

:source-highlighter: highlight.js

This document explains how the in-house `regmodel::RegisterMap` library
(`common/include/reg_map.h`, built on `common/include/reg_access.h`) can model
the **scratch CSR blocks** defined in tt-oca-hw for both SMC and SEP. It is a
practical companion to `doc/register-modeling-smc-vs-sep-csml.adoc` and the
UART retrofit in `smc/peripherals/uart/`.

[[answer]]
== Short answer

**Yes.** The SMC and SEP scratch register files are an ideal fit for
`RegisterMap`:

* eight plain read/write storage registers per instance;
* fixed byte offsets with no address banking;
* no FIFO ports, no W1C, no lock-gating;
* optional *observation-only* side effects (e.g. SEP virt-console write-tap on
  `SCRATCH[2]`) are expressible as `Register<Word>::on_write` callbacks without
  leaving the map.

`RegisterMap` is **not** appropriate for `smc/peripherals/scratchpad_ram` —
that block is a byte-addressable RAM, not a CSR file.

[[hw-ground-truth]]
== Hardware ground truth (tt-oca-hw)

All paths below are relative to the tt-oca-hw repository
(`tt-oca-hw/`).

=== SMC scratch

[cols="1,2",options="header"]
|===
| Item | Value

| RDL source
| `hw/smc/smc_misc/data/registers/rdl/scratch.rdl`

| Parent map
| `hw/smc/smc_misc/data/registers/rdl/misc_wrap.rdl`

| Register definition
| `SCRATCH[8]` — one 32-bit field `data[31:0]`, `sw=rw`, `hw=na`, reset `0`

| Stride / window
| 4-byte stride (`0x00` … `0x1C`); window size `0x20` (32 bytes)

| Instances in `misc_wrap`
| `scratch_cold` @ offset `0x0000`; `scratch_cold_warm` @ offset `0x0080`

| Absolute addresses (generated)
| `packaged_ip/ocah_include_dirs/ocah_smc_top_reg.svh` — e.g.
  `SMC_MISC_WRAP_SCRATCH_COLD` base `0xC000_2800`,
  `SMC_MISC_WRAP_SCRATCH_COLD_WARM` base `0xC000_2880`
|===

=== SEP scratch

[cols="1,2",options="header"]
|===
| Item | Value

| RDL source
| `meta/registers/rdl/sep_scratch.rdl`

| Parent map
| `meta/registers/rdl/och_sep_top.rdl`

| Register definition
| `SCRATCH[8]` — 64-bit register width, 64-bit access width; effective field
  `data[31:0]`, `sw=rw`, `hw=r`, reset `0`

| Stride / window
| 8-byte stride (`0x00` … `0x38`); window size `0x40` (64 bytes)

| Instances in `och_sep_top`
| `sep_scratch_cold` @ `BASE_ADDR + 0x1080_2000`;
  `sep_scratch_warm` @ `BASE_ADDR + 0x1080_2080`

| Absolute addresses (generated)
| `packaged_ip/ocah_include_dirs/ocah_och_sep_top_reg.svh` — e.g.
  `SEP_SCRATCH_COLD` base `0x1080_2000`,
  `SEP_SCRATCH_WARM` base `0x1080_2080`
|===

=== SMC vs SEP comparison

[cols="1,1,1",options="header"]
|===
| Property | SMC `scratch` | SEP `sep_scratch`

| Effective data width
| 32 bits | 32 bits (in a 64-bit CSR slot)

| Bus access width
| 32 bits (default RDL regwidth) | 64 bits (`regwidth` / `accesswidth` = 64)

| Offset stride
| `+4` | `+8`

| Hardware visibility
| `hw=na` (storage only) | `hw=r` (RTL exports `hwif_out.SCRATCH[i].data`)

| Typical firmware use
| post codes, SMC↔SEP handshakes, test markers | boot ROM status, cocotb flags,
  virt-console channel
|===

[[why-reg-map]]
== Why `RegisterMap` fits scratch CSRs

Scratch registers match the design intent of `reg_map.h`:

[cols="1,2",options="header"]
|===
| `RegisterMap` capability | Scratch CSR need

| `add(offset, name, reg)` dispatch
| Eight fixed offsets per instance — no `switch` per register

| `Register<Word>` mask contract
| Full-word RW: `read_mask = write_mask = 0xFFFF'FFFF` (or `0xFF` for 8-bit)

| `on_write` / `on_read` callbacks
| Optional observation (virt-console tap) without custom decode cases

| `for_each()` / `find()`
| Debug dumps, back-door access, reset-to-zero of the whole bank

| Stays out of `b_transport`
| Alignment, burst width, TLM response codes remain in the module
|===

Reference implementation already in-tree: UART `SCR`, `ECR`, and `ITR` use
`RegisterMap8` in `smc/peripherals/uart/`.

[[shared-constants]]
== Shared constants header

Transcribe offsets and masks once from the generated SVH or RDL. Example
layout (hand-written today; `common/tools/regmap_gen.py` can emit this from
the `.rdl` later):

[source,cpp]
----
// scratch_cfg.h — shared between SMC and SEP models
namespace scratch_cfg {

// SMC: hw/smc/smc_misc/.../scratch.rdl
struct smc {
    static constexpr unsigned NUM_REGS   = 8;
    static constexpr unsigned STRIDE     = 4;    // bytes
    static constexpr unsigned WINDOW     = 0x20; // bytes
    static constexpr uint32_t RMASK      = 0xFFFF'FFFFu;
    static constexpr uint32_t WMASK      = 0xFFFF'FFFFu;
    static constexpr uint32_t RESET      = 0u;
    static constexpr uint64_t OFF(unsigned i) { return i * STRIDE; }
};

// SEP: meta/registers/rdl/sep_scratch.rdl
struct sep {
    static constexpr unsigned NUM_REGS   = 8;
    static constexpr unsigned STRIDE     = 8;    // bytes (64-bit slots)
    static constexpr unsigned WINDOW     = 0x40; // bytes
    static constexpr uint32_t RMASK      = 0xFFFF'FFFFu; // data[31:0] only
    static constexpr uint32_t WMASK      = 0xFFFF'FFFFu;
    static constexpr uint32_t RESET      = 0u;
    static constexpr uint64_t OFF(unsigned i) { return i * STRIDE; }
};

} // namespace scratch_cfg
----

[[smc-model]]
== SMC model sketch

Model one `scratch` addrmap instance (cold **or** warm) as a small
`sc_module` with a `RegisterMap32` and eight `Register32` members.

=== Class layout

[source,cpp]
----
#include "reg_access.h"
#include "reg_map.h"
#include "sim_log.h"

class smc_scratch_bank : public sc_core::sc_module {
public:
    static constexpr unsigned N = scratch_cfg::smc::NUM_REGS;

    tlm_utils::simple_target_socket<smc_scratch_bank, 32> reg_socket{"reg_socket"};

    explicit smc_scratch_bank(sc_core::sc_module_name name);

    void b_transport(tlm::tlm_generic_payload& gp, sc_core::sc_time& delay);

private:
  // Storage: one Register32 per SCRATCH[i]
    std::array<regmodel::Register32, N> scratch_{};
    regmodel::RegisterMap32             regmap_;

    bool reg_read (uint64_t off, uint32_t& data);
    bool reg_write(uint64_t off, uint32_t data);
};
----

=== Constructor: register the bank

[source,cpp]
----
smc_scratch_bank::smc_scratch_bank(sc_core::sc_module_name name)
    : sc_core::sc_module(name)
{
    using cfg = scratch_cfg::smc;
    for (unsigned i = 0; i < N; ++i) {
        scratch_[i] = regmodel::Register32{cfg::RMASK, cfg::WMASK, cfg::RESET};
        regmap_.add(cfg::OFF(i), "SCRATCH_" + std::to_string(i), scratch_[i]);
    }

    SIM_LOG_INFO(this, "smc_scratch_bank: " << regmap_.size() << " registers");

    reg_socket.register_b_transport(this, &smc_scratch_bank::b_transport);
}
----

=== `reg_read` / `reg_write`: map-only decode

[source,cpp]
----
bool smc_scratch_bank::reg_read(uint64_t off, uint32_t& data)
{
    return regmap_.read(off, data);
}

bool smc_scratch_bank::reg_write(uint64_t off, uint32_t data)
{
    return regmap_.write(off, data);
}
----

=== `b_transport` (32-bit, 4-byte aligned)

[source,cpp]
----
void smc_scratch_bank::b_transport(tlm::tlm_generic_payload& gp,
                                   sc_core::sc_time&         delay)
{
    const uint64_t addr = gp.get_address();
    if (gp.get_data_length() != 4 || (addr & 3u) != 0) {
        gp.set_response_status(tlm::TLM_BURST_ERROR_RESPONSE);
        return;
    }
    if (addr >= scratch_cfg::smc::WINDOW) {
        gp.set_response_status(tlm::TLM_ADDRESS_ERROR_RESPONSE);
        return;
    }

    bool ok = false;
    uint32_t data = 0;
    if (gp.is_read()) {
        ok = reg_read(addr, data);
        if (ok) std::memcpy(gp.get_data_ptr(), &data, 4);
        SIM_LOG_TRACE(this, "read  off=0x" << std::hex << addr << " data=0x" << data);
    } else if (gp.is_write()) {
        std::memcpy(&data, gp.get_data_ptr(), 4);
        ok = reg_write(addr, data);
        SIM_LOG_TRACE(this, "write off=0x" << std::hex << addr << " data=0x" << data);
    }
    if (!ok) SIM_LOG_DEBUG(this, "decode miss off=0x" << std::hex << addr);

    gp.set_response_status(ok ? tlm::TLM_OK_RESPONSE : tlm::TLM_ADDRESS_ERROR_RESPONSE);
    delay += sc_core::sc_time(1.0, sc_core::SC_NS); // example access latency
}
----

=== Cold vs warm instances

Instantiate **two** `smc_scratch_bank` modules (or one module with a CCI
`instance_id`) at the bases from `ocah_smc_top_reg.svh`:

* `scratch_cold`      → `0xC000_2800`
* `scratch_cold_warm` → `0xC000_2880`

Each instance owns its own `RegisterMap32` and eight `Register32` values. Reset
policy: cold bank clears on cold reset; warm bank survives warm reset — implement
in `reset_proc()` by calling `scratch_[i].reset(0)` only for the cold instance.

[[sep-model]]
== SEP model sketch

SEP scratch is the same *logical* bank (eight RW words) but on a **64-bit**
AXI-Lite bus with 8-byte stride. Two modeling options:

[cols="1,2",options="header"]
|===
| Approach | When to use

| **A — `RegisterMap32` + 64-bit adapter** (recommended)
| Store the effective 32-bit value in `Register32`; in `b_transport`, accept
  only 8-byte aligned 64-bit transactions, read/write the low 32 bits through
  the map, return `0` in bits `[63:32]` on read. Matches RDL field `data[31:0]`.

| **B — `RegisterMap64` with `WMASK = 0xFFFF'FFFF`**
| Single 64-bit register image; upper lane always read-as-zero / write-ignored
  via mask. Slightly more literal to `regwidth=64` but duplicates lane policy in
  the `Register` object.
|===

=== Option A: `RegisterMap32` with 64-bit `b_transport`

[source,cpp]
----
bool sep_scratch_bank::reg_read(uint64_t off, uint64_t& data64)
{
    uint32_t lo = 0;
    if (!regmap_.read(off, lo)) return false;
    data64 = lo; // RDL: only data[31:0] defined; upper bits RAZ
    return true;
}

bool sep_scratch_bank::reg_write(uint64_t off, uint64_t data64)
{
    const uint32_t lo = static_cast<uint32_t>(data64);
    return regmap_.write(off, lo);
}
----

`b_transport` validates `length == 8` and `(addr & 7) == 0`, then calls the
helpers above. Offsets use `scratch_cfg::sep::OFF(i)` (`0`, `8`, `16`, … `56`).

=== Hardware read port (`hw=r`)

RTL drives `hwif_out.SCRATCH[i].data` from the stored register. In simulation,
other modules that need the hardware-side view should call `scratch_[i].raw()`
(not `read()`, which applies the software read mask). No extra map entry is
required.

=== Optional write-tap (virt console)

Firmware writes boot-time console characters to `SEP_SCRATCH_COLD_SCRATCH_2`
(offset `0x10`). The VP observes this without changing storage semantics:

[source,cpp]
----
// In constructor, after scratch_[2] is default-constructed:
scratch_[2].on_write([this](uint32_t cur, uint32_t in) -> uint32_t {
    const uint32_t next = regmodel::apply_write_mask(cur, in, scratch_cfg::sep::WMASK);
    if (virt_console_) virt_console_->on_word(in); // observation only
    return next;
});
----

The register still dispatches through `regmap_`; the callback replaces the
default mask-merge inside `Register32::write()`.

=== Cold vs warm instances

Same pattern as SMC: two `sep_scratch_bank` instances at

* `SEP_SCRATCH_COLD` base `0x1080_2000`
* `SEP_SCRATCH_WARM` base `0x1080_2080`

Warm-reset tests in tt-oca-hw DV expect cold scratch to survive certain reset
sequences while warm scratch may clear — encode that in each instance's
`reset_proc()`, not in `RegisterMap`.

[[integration-checklist]]
== Integration checklist

Use this when adding a new scratch bank model to SMC or SEP:

. Add `common/include` to `target_include_directories` in `CMakeLists.txt`.
. `#include "reg_access.h"`, `reg_map.h`, and optionally `sim_log.h`.
. Define `scratch_cfg` constants from tt-oca-hw RDL / generated SVH.
. Create `std::array<Register32, 8>` (or `Register32` members) + one `RegisterMap32`.
. In the constructor, loop `regmap_.add(OFF(i), "SCRATCH_i", scratch_[i])`.
. Implement `reg_read` / `reg_write` as thin `regmap_.read` / `regmap_.write` wrappers.
. Keep alignment, window-size, and TLM status handling in `b_transport`.
. Use `SIM_LOG_TRACE` for transactions, `SIM_LOG_DEBUG` for decode misses.
. For SEP observation hooks, prefer `on_write` on the specific `Register32` over
  a special-case offset in `reg_write`.
. Do **not** use `RegisterMap` for `scratchpad_ram` — use a byte array + DMI
  path instead.

[[csml-alternative]]
== Relation to SEP CSML / `SEPMemory`

Today some SEP platforms model scratch through CSML `SEPMemory` with a
platform-injected write-tap (`sep/peripherals/sep_virt_console/`). A
`reg_map.h` model is the hand-written equivalent:

[cols="1,1,1",options="header"]
|===
| Concern | CSML `SEPMemory` | `regmodel::RegisterMap`

| Address decode
| Framework-provided | `RegisterMap::read` / `write`

| Mask / access policy
| Generated register classes | `Register32` + masks from RDL

| Write observation
| External tap on memory port | `Register::on_write` callback

| Dependency
| External CSML submodule | Header-only, in-repo
|===

For a new SEP scratch peripheral model, `RegisterMap` is sufficient and avoids
CSML coupling. Existing CSML-based platforms can stay on CSML until migrated.

[[summary]]
== Summary

[cols="1,2",options="header"]
|===
| Question | Answer

| Can `reg_map.h` model SMC/SEP scratch CSRs?
| **Yes** — they are plain RW banks with fixed offsets.

| Best reference in this repo?
| `smc/peripherals/uart/` (`RegisterMap8` for `SCR` / `ECR` / `ITR`).

| SMC vs SEP difference in the model?
| SMC: 32-bit bus, 4-byte stride, `RegisterMap32`. SEP: 64-bit bus, 8-byte
  stride, `RegisterMap32` for storage + 64-bit `b_transport` adapter.

| What is out of scope?
| `scratchpad_ram` (memory), address banking, CSML migration of unrelated IPs.
|===
