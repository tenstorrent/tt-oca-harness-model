This document is the design and as-built record for interconnecting the
SMC (`smc-vp`) and SEP (`sep-vp`) virtual platforms with AXI over a
die-to-die (D2D) link. The RTL in `tt-oca-hw` / `tt-oca-harness`
(`hw/sys/smu/rtl/smu.sv`) is the reference architecture. The single-die
`smu-vp` platform, the SMU crossbar and window-remap models, the SEP
chiplet-boundary sockets, and the AOU (AXI-over-UCIe) LT stub are
**implemented**. Cycle-accurate FDI/UCIe PHY and a two-die `smu-d2d-vp`
remain out of scope; <<missing>> lists only what is still open.

[[hw-reference]]
== Hardware Reference Architecture (tt-oca-hw)

All paths below are relative to the `tt-oca-hw` repository root.

=== The SMU composite

In OCAH, SMC and SEP are never wired directly at a chiplet boundary in
isolation — they are composed, together with the DTP (Debug & Test Ports),
into the **SMU (System Management Unit)**
(`hw/smu/rtl/smu.sv`, see `doc/architecture.adoc` and
`doc/integration_guide.adoc`). The SMU is the instantiable subsystem; its
sole chiplet-facing AXI boundary is the `smu_axi_in` / `smu_axi_out` pair
(`hw/smu/doc/port_table.adoc`), which attaches to the SMN (System Management
Network).

=== The three SMC/SEP AXI paths inside the SMU

The RTL provides **three** distinct AXI paths between/around SMC and SEP:

[cols="<16%,<34%,<50%",options="header"]
|===
|Path |RTL route |Notes

|SEP -> SMC (dedicated)
|`sep.sep_ext_to_smc_axi_req_o` ->
`axi_window_remap` (`sep_ext_to_smc_axi_local_alias_remap`) ->
cross-package `AXI_ASSIGN_*` -> `smc.sep_axi_in_req_i`
(`hw/smu/rtl/smu.sv` lines ~998-1107)
|Point-to-point, **bypasses the crossbar**. The window remap translates the
SEP's SMC window `[SEP_SMC_REGION_BASE, +SEP_SMC_REGION_SIZE)` =
`[0x4000_0000, +1 GiB)` down to alias base `0x0`
(`hw/smu/rtl/smu_pkg.sv`), i.e. SEP address `0x4000_0000 + X` appears at the
SMC `sep_axi_in` port as `X`, which the SMC fabric then forces into its local
alias window (`0xC000_0000 \| X`).

|SMU crossbar (3x3)
|`smu_axi_xbar` (`hw/smu/rtl/smu.sv` line ~1026); masters `sep_out`,
`smc_out`, `ext_in`; targets `sep_in`, `smc_in`, `ext_out`
|Non-reflexive: each master reaches the other two targets, never its own
inbound port. `smc_out` is the SMC fabric's `output_axi`; `sep_in`/`smc_in`
feed `axi_iw_converter` instances (xbar 10-bit ID -> 6-bit ID) before
entering `sep_smn_inbound_axi` / `smc sys_axi_in`. Routing uses the
programmable SEP/SMC global apertures; `ext_out` is the static catch-all
(`0x0000_8000_0000` to top of 56-bit space).

|SMC/SEP <-> chiplet (D2D leg)
|SMU boundary `smu_axi_in_req_i` / `smu_axi_out_req_o`
(`hw/smu/doc/port_table.adoc`)
|This is where inter-chiplet traffic enters/exits. In a multi-die system the
SMN plus an **AXI-over-UCIe (AoU) bridge** and a UCIe PHY carry these AXI
transactions to the remote die's SMU. Neither the SMN fabric nor the AoU
bridge RTL ships with OCAH (see <<missing-hw>>). The VP binds this pair
through `aou_core` (see <<as-built>>).
|===

=== Programmable address map contract

Routing is **runtime-programmable**; firmware must program both apertures
during early boot, before any cross-subsystem traffic, and the two apertures
must not overlap (`doc/integration_guide.adoc`, section
"SMU AXI Crossbar Address Map"):

[cols="<30%,<30%,<40%",options="header"]
|===
|CSR pair |Reset default |Controls

|SMC `GLOBAL_BASE` / `REGION_SIZE`
|`0x4000_0000` / `0x0100_0000` (16 MiB)
|SMU `ext_in` -> `smc_in` routing; SMC local/global aperture split;
SEP-to-SMC decode window (`smc_global_base_addr_i` into the SEP demux)

|SEP `SEP_GLOBAL_BASE_ADDR` / `SEP_REGION_SIZE`
|(integrator-assigned) / `0x0100_0000` (16 MiB)
|SMU `ext_in` -> `sep_in` routing; SEP inbound global-to-local remap
|===

Additionally, the SMC fabric has its own local-alias scheme: `LOCAL_BASE`
(RO, `0xC000_0000`) and the alias-remap regions translate local-alias
addresses to global system addresses for outbound traffic
(`hw/smc/doc/fabric.adoc`).

[[sim-today]]
== Standalone platforms (smc-vp / sep-vp)

The two subsystem VPs remain independently runnable. Integration happens
only in `smu-vp` (<<as-built>>); standalone bindings keep historical
`smc-vp` / `sep-vp` firmware behavior.

=== SMC virtual platform (`vp/platform/smc`, executable `smc-vp`)

The SMC platform exports the chiplet-facing boundary where the RTL has it:

* `sys_axi_in`, `jtag_axi_in`, `sep_axi_in` — 64-bit target sockets on
  `smc_platform`, forwarded into the fabric (`fwd_sys_axi` / `fwd_jtag_axi`
  / `fwd_sep_axi`).
* `output_axi` — 64-bit initiator for outbound (global-aperture) traffic.
* `aou_axi_s` / `aou_axi_m` — local AOU AXI slave/master, re-exported so
  `smu-vp` can bind the xbar `ext_out`/`ext_in` pair. AOU CSRs sit on the
  periph router at `0xC000_4000` (window `0x80`); `irq_o` is aggregated
  into PLIC source ID 27.
* `smc_fabric` models alias remap, the local/global aperture split
  (`GLOBAL_BASE` / `LOCAL_BASE` / `REGION_SIZE`), the inbound filter on
  `sys_axi_in`, and local-only routing on `sep_axi_in` (no filter, no
  remap — dedicated-port behavior).

Standalone `smc-vp` (`vp/platform/smc/main.cpp`) binds `output_axi` to
`stub_sysmem`, the three inbound sockets to idle initiators, `aou_axi_s`
to an idle initiator, and `aou_axi_m` to a remote stub. The local AOU is
`connect_peer`'d to an in-platform `aou_peer_` (remote-die stand-in).

=== SEP virtual platform (`vp/platform/sep`, executable `sep-vp`)

Devices hang off an internal 32-bit `SimpleBus` (`sep_platform.hpp`). Three
chiplet-boundary sockets are exported:

* `sep_ext_to_smc_axi` — 64-bit initiator for the dedicated SEP→SMC
  window. Driven by `sep_smc_global_port` when `forward_en=true`.
* `sep_smn_inbound_axi` — 64-bit target from the SMU crossbar (RTL
  `smn_inbound_axi`): inbound filter → global-to-local remap → bus.
* `sep_smn_outbound_axi` — 64-bit initiator after the outbound filter
  (RTL `smn_outbound_axi`). The SMU window (live
  `SMU_GLOBAL_BASE_ADDR` / `SMU_REGION_SIZE`) merges into
  `outbound_filter_mux` (base re-added so the filter sees global
  addresses), then `outbound_filter_to_smn` (32→64).

Standalone `sep-vp` keeps `smc_global.forward_en=false` (seeded RW
fallback, first 2 MiB of the 1 GiB SEP→SMC window), binds
`sep_smn_inbound_axi` to an idle initiator, and sinks both outbound
initiators. Window-local offsets still match the SMC local map (SMC SRAM
at offset `0x60000` == `0xC006_0000`).

Mailbox: the SEP VP has a real mailbox model; the SMC fabric's
`to_mailbox` is still a stub (see <<missing-sim>> item 9).

*Dedicated SEP→SMC.* SEP `sep_ext_to_smc_axi` →
`smu::axi_window_remap<64,64>` (`sep2smc_remap`, window
`[0x4000_0000, +1 GiB)` → alias `0x0`, per `smu_pkg.sv`) → SMC
`sep_axi_in`. `smu-vp` presets `och_sep_ss1.smc_global.forward_en=true`
so the window is a live forwarder, not the seeded stub.

*Crossbar.* SMC `output_axi` → `smu_axi_xbar.smc_out`; `smc_in` → SMC
`sys_axi_in`; `sep_in` → SEP `sep_smn_inbound_axi`; SEP
`sep_smn_outbound_axi` → `smu_axi_xbar.sep_out`. Catch-all addresses on
either outbound master exit `ext_out`.

*D2D / AoU LT stub.* `ext_out`/`ext_in` bind through the local
`aou_core` (AXI-over-UCIe model in `aou/`), matching OCAH's placement of
AoU on `smu_axi_in`/`smu_axi_out`. The peer AOU inside `smc_platform` is
the remote-die stand-in (`connect_peer`; peer `axi_m` → `stub_sysmem`).
Catch-all traffic forwards only after firmware writes
`aou_init.activate_start` (both cores ENABLED); until then `axi_s`
returns `TLM_COMMAND_ERROR_RESPONSE`. Peer `axi_s` is idle — there is no
remote SMU master in this single-die VP.

=== Aperture contract

The SEP inbound window has one driver: `sep_cpu_ctrl`
`SEP_GLOBAL_BASE_ADDR` / `SEP_REGION_SIZE`, exported as
`sep_global_base_addr_signal` / `sep_region_size_signal` and bound into
the xbar (`sep_global_base_addr_i` / `sep_region_size_i`). `smu-vp`
seeds those CSRs (standing in for early firmware) and no longer presets
`smu_xbar.sep_global_base` independently:

* `och_sep_ss1.sep_global_base` = `0x5000_0000`; if the ini widens
  `smu_xbar.sep_region_size`, the same value is copied into
  `och_sep_ss1.sep_region_size` so the CSR window matches what the
  xbar will route.
* `smu_xbar.smc_global_base` = `0x4000_0000` (SMC `GLOBAL_BASE` reset).
* `och_sep_ss1.smc_global_base` / `smc_region_size` =
  `SEP_SMC_REGION_BASE` / `SIZE` (`0x4000_0000` / 1 GiB) so the
  dedicated demux window matches `axi_window_remap`.
* `vp/platform/smu/config/smc_smu_vp.ini` widens `sep_region_size` to
  512 MiB so the SEP SRAM alias at `0x6000_0000` is inside the
  aperture, and lowers `dut.cluster.mmio_lo` to `0x4000_0000` so SMC
  CPU traffic to the global apertures reaches the fabric.

The SMC scratchpad is at **`0xC006_0000`**, not `0xC004_0000` (that slot
is the boot ROM). SEP→SMC traffic must use window offset `0x6_0000+`.

=== Sidebands

SMC-facing legs carry `smc::smc_axi_extension`. The SEP boundary neither
consumes nor produces that type; the crossbar forwards payloads
unchanged, so no sideband bytes are reinterpreted.

[[steps]]
== Interconnection Steps (simulation)

The target — `vp/platform/smu`, executable `smu-vp` — instantiates
`smc_platform`, the SEP subsystem, the crossbar, and the AOU LT stub,
mirroring `hw/smu/rtl/smu.sv`. Each step below records what landed.

=== Step 1 — Expose the SEP VP boundary (done)

1. *SEP → SMC (outbound):* `sep_smc_global_port` replaces the
   `smc_global` `SEPMemory` stub. `forward_en=false` keeps the seeded
   fallback for standalone `sep-vp`; `forward_en=true` re-adds
   `window_base` and forwards on `sep_ext_to_smc_axi`.
2. *SMC → SEP (inbound):* `sep_smn_inbound_axi` feeds inbound filter →
   `smn_inbound_remap_adapter` (subtract `sep_global_base`) → internal
   bus.
3. *SEP → SMN/AOU (outbound):* `sep_smn_outbound_axi` is the filter
   output (SMU window + AP/STEE remaps). Standalone `sep-vp` sinks it;
   `smu-vp` binds `xbar.sep_out`.

The 32↔64 width bridge is at the three boundary adapters
(`sep_smc_global_port`, inbound remap, `outbound_filter_to_smn`).

=== Step 2 — Model the SMU AXI crossbar (done)

`vp/platform/smu/inc/smu_axi_xbar.h`: 3x3 non-reflexive router. The SEP
aperture follows the bound CSR ports; the SMC aperture is CCI. `ext_out`
is the catch-all. Response routing is by TLM socket association (no
ID-remap table at LT fidelity).

=== Step 3 — Model the D2D link (done as AOU LT stub)

The generic two-socket `d2d_link` sketched below was **not** built as a
separate module. Single-die `smu-vp` uses `aou_core` on
`ext_out`/`ext_in` plus an in-platform peer AOU as the remote-die
stand-in — the OCAH placement (AoU between SMU/SMN and the UCIe PHY).
No UCIe packetization, retry, or link training (RTL has no AoU; Boot ROM
`train_d2d` is Unsupported).

A future two-die system would still look like:

[source]
----
  +------------------+                      +------------------+
  | die0  smu-vp     |                      | die1  smu-vp     |
  |                  |     AOU / D2D        |                  |
  |   ext_out o------+--------------------->+----> o ext_in    |
  |   ext_in  o<-----+<---------------------+----- o ext_out   |
  +------------------+                      +------------------+
----

=== Step 4 — Assemble `smu-vp` (single-die done; two-die open)

Wiring is in `vp/platform/smu/src/smu_platform.cpp` (`smu_platform`
owns both subsystems and the interconnect): dedicated remap, all four
crossbar legs, AOU on `ext_in`/`ext_out`.
`smu-d2d-vp` (two `smu_platform`s joined by a link, non-overlapping
apertures) is not built.

=== Step 5 — Firmware/address-map bring-up contract (done)

`sep_cpu_ctrl` drives `sep_global_base_addr_o` / `sep_region_size_o`;
`smu-vp` binds those signals into the xbar so a firmware reprogram
moves both sides together. CCI presets seed the CSRs (and the SMC
aperture) at elaboration — see <<as-built>>. Catch-all (miss both
apertures) is `ext_out`, gated by AOU ENABLED.

=== Step 6 — Sideband/extension mapping (done by construction)

SMC-facing sockets carry `smc::smc_axi_extension`. The SEP boundary does
not use that type; the xbar forwards payloads unchanged. TLM call
association replaces the RTL ID-remap table.

=== Step 7 — Tests (done for single-die)

Unit tests for the crossbar, window remap, and AOU; platform firmware
in `sw/smu-vp-tests/` (link, xbar tokens, 50-beat traffic, AOU ext-out
from both CPUs). Two-die scratchpad-over-link is not written.

[[missing-hw]]
=== Missing in tt-oca-hw (reference RTL)

1. **AoU (AXI-over-UCIe) bridge RTL** — described in
   `doc/architecture.adoc` as the protocol bridge between the internal AXI
   fabric and the UCIe D2D PHY, but **no RTL exists** in the repository
   (no `aou`/`ucie` modules under `hw/`; only the placeholder
   `doc/aou.placeholder.adoc`). It is an adopter/future component.
2. **SMN (System Management Network) fabric** — the SMU boundary
   `smu_axi_in`/`smu_axi_out` attaches to it, but
   `doc/integration_guide.adoc` section "System Management Network (SMN)
   Integration" is a stub ("currently under development") and only the
   placeholder `doc/smn.placeholder.adoc` exists. No SMN RTL ships.
3. **UCIe PHY** — explicitly adopter-specific (`doc/architecture.adoc`,
   Power Domains); only power/reset hooks (`isolate_req_o`,
   `ss_reset_ctrl_o`) are provided.
4. **D2D link training firmware** — `train_d2d` (MsgID 0x3) returns
   Unsupported in the SMC Boot ROM; training is deferred to BL#1/application
   software (`fw/.../specification/smc_rom.adoc`).

Consequence for the sim: there is no RTL-level D2D contract to model
against beyond "AXI in, AXI out". The LT stand-in in <<steps,Step 3>> is
therefore the correct fidelity until AoU/SMN RTL exists.
