== Working with Documentation

tt-oca-sim ships next to the open hardware tree. The two repositories
do not carry the same information.

The hardware TRM (tt-oca-hw / tt-oca-harness) owns architecture,
register maps, programming sequences, and interrupt numbering.

This repository owns the SystemC/TLM-2.0 implementation of those
blocks, the model test plan, and how to run the tests.

Do not copy TRM chapters, RDL tables, or firmware how-tos into this
tree. Point at the TRM and write only what is true of the model.

=== Document formats

Structured pages are AsciiDoc (`.adoc`). README files meant to be read
on GitHub stay Markdown (`.md`).

Every hand-authored AsciiDoc file carries:

[source,asciidoc]
----
// SPDX-License-Identifier: Apache-2.0
// SPDX-FileCopyrightText: 2026 Tenstorrent USA, Inc.
----

Write in the present tense. Do not narrate what changed.

=== What belongs where

[cols="30%,35%,35%",options="header"]
|===
|Topic |TRM (hardware repo) |This repo
|Block purpose, algorithms, address map, CSRs |Yes |No. Cite the TRM.
|Firmware programming sequences |Yes |No.
|SystemC class tree, TLM sockets, `sc_in` / `sc_out` |No |Yes
|CCI knobs, LT timing, backends, modeling gaps |No |Yes
|Standalone unit-test plan |No |Yes
|How to build and run tests |No |Yes
|===

When the VP and RTL disagree, record the modeling gap on the
implementation page. Do not publish a second copy of the RTL map.

=== IP pages

Each modeled IP owns `doc/` next to `include/`, `src/`, and `test/`:

----
<subsystem>/peripherals/<ip>/
  README.md                 # GitHub landing: one-line role + how to run
  doc/
    index.adoc              # pointer to the TRM + include list
    implementation.adoc     # SystemC/TLM-2.0 model
    test_plan.adoc          # cases + how to run them
----

`index.adoc` includes `implementation.adoc` then `test_plan.adoc`.

* IP title: `====`
* Page title: `=====`
* Subsections: `======`

Every page starts with an `[[anchor]]`.

Do not add `architecture.adoc`, `memmap.adoc`, or `programming.adoc`
here. Those names are TRM pages. Do not add new `01_` / `02_` / `03_`
Markdown specifications.

.Mapping from the previous numbered Markdown
[cols="45%,25%,30%",options="header"]
|===
|Previous file |Keep as |Drop (lives in the TRM)
|`01_*_Specification`, `registers.md`, `programmers_guide.md` |— |Yes
|`02_*_HighLevel_Design` / `02_*_LowLevel_Design` |`implementation.adoc` (TLM only) |RTL/functional restatement
|`03_*_Test_Plan` |`test_plan.adoc` |—
|`00_Integration_and_Placement` |`implementation.adoc` (sockets, bind site) |Address-map copy
|===

Adams Bridge (`sep/peripherals/adams_bridge/doc/`) is the reference.

=== Subsystem books

SEP and SMC books live under `sep/doc/` and `smc/doc/`. They describe
the virtual platform, not the silicon.

[cols="30%,70%",options="header"]
|===
|File |Content
|`index.adoc` |Book title and include list
|`implementation.adoc` |How `sep-vp` / `smc-vp` is wired in SystemC/TLM-2.0
|`test_plan.adoc` |How to run standalone, platform, and firmware tests
|===

Do not add `overview.adoc`, `memory_map.adoc`, `crypto.adoc`, or
`periphs.adoc` copies of the TRM.

=== Implementation page

State:

* Class and file layout
* TLM sockets and SystemC ports, and where the platform binds them
* Threads, callbacks, and pluggable backends
* CCI parameters and LT timing
* What the model deliberately omits versus RTL

Do not restate command encodings, register tables, or algorithm sizes.

=== Test-plan page

State:

* Standalone bench layout and success criteria
* The case table (what the model test proves)
* Exact commands to run the standalone suite
* Platform / firmware tests and the commands to run those

=== Tables and source

Use AsciiDoc tables. Fence commands with `[source,bash]` and model
snippets with `[source,cpp]`.
