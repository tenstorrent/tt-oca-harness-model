# GPIO

## Overview

This directory contains the GPIO IP and a basic cocotb testbench. The General Purpose IO component is used for:
- Configuration straps (input)
- General input and output signalling facilities
- Bit-banging low speed protocols

Included in the IP are the GPIO interface, an example GPIO functional model, and an example GPIO shim to connect the interface and the model.

## Generating the IP

To generate the GPIO IP, run the following command:

```bash
python3 generate_ip.py -i <io-port-type>
```

Replace `<io-port-type>` with one of the following options:

- `apb4`
- `axi4-lite`
- `apb4-flattened`
- `axi4-lite-flattened`

### Key Features

* **Data Interface Control:** Register-driven or LSIO interface selection with programmable direction
* **Security & Access Control:** Register access filtering with AXIL/APB protection level requirements
* **Interrupt Generation:**: Active-high/low level, rising/falling edge


## Architecture

### Module Hierarchy

```
gpio (Top-level wrapper)
├── gpio_filter (protection-level access control)
└── Register Interface (APB or AXI-Lite)
    └── gpio_intf_reg (Generated register interface)
```


## Clocks and Reset

The GPIO IP operates on a single clock and reset domain, with no internally generated clocks or resets.

### Clock Domains

- Input clocks:
  - **clk_i**: Functional logic + Register interface clock (APB4/AXI4-Lite)

### Reset Domains

- **`rst_ni`**: Primary synchronous reset (active low)


## Testing Framework

### Cocotb Test Environment

The testbench uses Python-based cocotb framework for basic verification. The testbench is generated using the `generate_ip.py` script and supports both APB4 and AXI4-Lite interfaces. The testbench module contains two full "units" each consisting of a GPIO interface, GPIO shim, and GPIO model. These two units are fully independent and only connected via a fake "pad".

Two testbench areas are provided: "tb_vcs" uses a VCS compilation+sim, while "tb" uses a Verilator compilation+sim.

* **Test Files**:
  - `tb_gpio.sv`: SystemVerilog testbench wrapper.
  - `test_gpio.py`: Main test file
  - `Makefile`: Build and simulation control

### Test Coverage

* **test_rw_chip2pad**: Read/write from gpio_intf_reg
* **test_read_filter**: Enable the read filter. Check that reads are blocked if the prot requirement is not met, and passed through if it is.
* **test_write_filter**: Enable the write filter. Check that writes are blocked if the prot requirement is not met, and passed through if it is.
* **test_rx_tx**: Write data to one GPIO and check that is is read by the other.
* **test_lsio_interface**: Check that the GPIO data lines can be controlled by the LSIO interface.
* **test_shim_register_access**: Check the the gpio_ctrl_reg contained in the shim is accessible.


## Register Interface

The GPIO provides the following CSRs:

### gpio_intf_reg
- **ACCESS_FILTER**: Enable filters and set prot requirement
- **DATA_CTRL**: Data and direction control/enable, interface select

### gpio_ctrl_reg
- **CONTROL**: GPIO model-specific configuration/control/status

## Quick Setup Guide

### Prerequisites Setup

```bash
# from tt-och root directory
source envsetup
cd hw/ip/gpio
```

### Running Tests

```bash
# Generate IP first (required before testing)
cd ..
python3 generate_ip.py -i apb4

# Navigate to testbench directory
cd tb
or
cd tb_vcs

# FOR TB_VCS
make clean; make filelist; make

# FOR TB
make clean; make

# Run a specific test (after cleaning / filelist generation if necessary)
make TESTCASE=test_rx_tx

```
