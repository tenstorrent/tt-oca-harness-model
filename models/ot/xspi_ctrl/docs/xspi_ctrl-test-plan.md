# xspi_ctrl Test Plan

**IP:** IP6522 (xSPI Controller) + IP6182 (Soft PHY)
**Model Scope:** Loosely Timed (LT) SystemC TLM 2.0 functional model
**Document Version:** 1.0
**Date:** 2026-03-04

---

## 1. Introduction

### 1.1 Purpose and Scope

This test plan defines the unit-level verification strategy for the xspi_ctrl SystemC TLM 2.0 model. The model implements the Cadence IP6522 xSPI Controller combined with the IP6182 xSPI Octal-DDR Soft PHY at the Loosely Timed (LT) abstraction level.

The test plan covers:
- All eight register sub-regions (56 registers total) with correct reset values, access types, and callbacks.
- All six operating modes: Direct, STIG, PIO, ACMD/CDMA, XIP, and Boot.
- Power-on Reset (PoR) and SFDP discovery flow.
- Interrupt architecture (thread completion, thread error, general `intr_status` bits).
- DMA interface behavior on `i_dma_socket` and `t_axi_slave_socket`.
- Configuration parameter effects (`NUM_TARGETS`, `n_threads`, `boot_available`, `dma_addr_width`).
- Mode-dependent `cmd_reg0`–`cmd_reg5` bitfield layouts.
- Error and edge-case handling.

### 1.2 Test Environment

Tests run in a SystemC TLM 2.0 testbench. The testbench instantiates the `xspi_ctrl` module under test and provides:
- A register-access driver connected to `t_reg_socket` for all software register reads and writes.
- A Direct-mode AXI slave driver connected to `t_axi_slave_socket` for memory-mapped flash transactions.
- A PoR driver connected to `PoR_input_signals` delivering `xspi_PoR_trans` extension payloads.
- Flash device stub models connected to `xspi_bus_socket[0..N-1]` that record incoming `cdns_extension` payloads and return configurable response data.
- A system memory stub connected to `i_dma_socket` that serves descriptor fetch reads, data DMA reads/writes, and descriptor status writeback writes.
- Signal monitors on `int_out` and `reset_in`.

Initialization sequence for every test: assert `reset_in` (drive low) to reset the model, deassert `reset_in` (drive high), deliver a `xspi_PoR_trans` write on `PoR_input_signals` to complete initialization, then verify `ctrl_status.init_comp` = 1 before proceeding with mode-specific register programming.

### 1.3 Pass/Fail Criteria

A test **passes** when all of the following conditions are simultaneously true at the end of the test:
- All register reads return the expected values documented in the Expected Result.
- All `xspi_bus_socket` transactions carry the correct `cdns_extension` fields (opcode, bank_num, address, data_bytes, instr_type) as documented.
- All `i_dma_socket` transactions (descriptor fetch, data DMA, status writeback) carry correct addresses, byte counts, and data payloads.
- `int_out` signal state matches the expected interrupt assertion or de-assertion condition.
- No unexpected TLM errors are reported by the testbench.

A test **fails** if any expected register value, socket transaction field, or signal state does not match the documented Expected Result.

## 2. Test Categories

1. **Register Access Tests** — Reset values, RO/WO/W1C enforcement, reserved-field behavior.
2. **Direct Mode Tests** — AXI READ/WRITE translation, address remapping, bank selection.
3. **STIG Mode Tests** — All five handlers, INSTR_LINK chaining, completion/interrupt.
4. **PIO Mode Tests** — All six CMD_TYPEs, multi-thread, DMA pointer, thread status.
5. **ACMD/CDMA Mode Tests** — Descriptor fetch/execute/writeback, CONT chaining, INT flag, MB_XIP_EN, error handling.
6. **XIP Mode Tests** — Entry/exit mode bytes, non-READ rejection, per-bank enable.
7. **Boot Mode Tests** — Boot image config record, DMA transfer, success/error reporting.
8. **PoR and SFDP Tests** — Discovery flow, sequence register auto-population, discovery_inhibit.
9. **Interrupt Architecture Tests** — W1C clear, enable masking, `int_out` assertion/de-assertion, both paths.
10. **Mode-Dependent Register Tests** — `cmd_reg0`–`cmd_reg5` layout verification per mode.
11. **Configuration Parameter Tests** — `NUM_TARGETS`, `n_threads`, `boot_available`, `dma_addr_width` effects.
12. **Error and Edge Case Tests** — `cmd_ignored`, busy thread, misaligned descriptor, invalid mode, DMA bus error.
