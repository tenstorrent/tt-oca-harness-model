= SMC SystemC/TLM2.0 Integration Guide
:toc:
:toclevels: 4
:sectnums:

== Purpose

This guide describes how to integrate the SMC SystemC/TLM2.0 models under
`/Users/pdroy/tt-oca-sim/smc` so they track the RTL subsystem connected under
`/Users/pdroy/tt_oca_hw/tt-oca-hw/hw/smc`.

The SystemC platform should be a firmware-oriented, loosely timed model. It
does not need cycle-accurate AXI arbitration, CDC, pad, PLL, or SRAM macro
timing, but it must preserve the programmer-visible contract:

* the same local and global SMC address map,
* the same CPU, fabric, peripheral, interrupt, reset, and memory topology,
* equivalent register side effects for modeled blocks,
* controlled responses or stubs for RTL-connected blocks that do not yet have
  SystemC models,
* CCI-based configuration for runtime and structural knobs,
* TLM generic payloads carrying enough AXI metadata for filtering, tracing, and
  future access-control tests.

== Integration Principles

* Treat `smc_top_reg.svh` and the RDL-generated firmware headers as the
  address-map source of truth. Do not create a second hand-maintained map in
  the SystemC platform.
* Keep all new model parameters as `cci::cci_param` members. Sizing parameters
  must be immutable; runtime delays and feature toggles may be mutable.
* Use `tlm_utils::simple_target_socket` and `simple_initiator_socket` as the
  current models do. Model bus timing with annotated delay, not `wait()` inside
  `b_transport`.
* Use `smc_axi_extension` on outgoing CPU and fabric transactions whenever AXI
  source ID, AXI ID, protection, security, or lock information matters.
  Before building the full platform, converge the memory models on the same
  canonical extension definition used by the CPU cluster so filters and monitors
  see one metadata type throughout the SMC.
* Use `regmodel` helpers from `common/include/reg_access.h` and
  `common/include/reg_map.h` for new or edited hand-written register models.
* Use `sim_log.h` for routine construction, decode, and transaction logs in new
  or edited models.
* Bind unmodeled RTL-connected peripherals to explicit stubs rather than
  leaving decode holes that cause firmware to hang without diagnostics.

== RTL Hierarchy to Mirror

=== Top-Level Boundary: `smc.sv`

`smc.sv` is the external chiplet-facing wrapper. It exposes:

* clocks: `clk_smc_i`, `clk_ref_i`, `clk_periph_i`, `clk_telemetry_i`,
* reset/power: `powergood_i`, `rst_cold_ni`, cool reset, scan reset, test
  enable,
* AXI ingress: system, JTAG, SEP, and SMC OTP/JTAG,
* AXI egress: filtered/remapped system output,
* AXI-Lite/APB-style external ports for PLL, PVT, GPIO control, eFuse bank,
  DTP CSR, and adopter extension,
* protocol pins and sideband: GPIO, SPI, UART, I2C, I3C, telemetry ATB, OCTS,
  JTAG debug, DFD/XTrigger, lifecycle, straps, mailbox interrupts, reset unit
  subsystem controls,
* CPU memory macro ports for ROM, scratch RAM, and L1 cache SRAMs.

In SystemC, create an `smc_platform`/`smc_top` module with a simplified but
compatible boundary:

* TLM target sockets for `sys_axi_in`, `jtag_axi_in`, `sep_axi_in`, and optional
  OTP/JTAG access.
* TLM initiator socket for `output_axi`.
* Signal ports or CCI presets for straps, lifecycle state, chiplet role,
  boot-stall override, FLR, external interrupts, SEP mailbox interrupts, and
  reset completion.
* Internal instances of `smc_fabric`, `smc_cpu_cluster`, `reset_unit`, PLIC,
  CLINT, memories, UART/I3C wrappers, and stubs for unmodeled blocks.

=== Core Logic: `smc_base.sv`

`smc_base.sv` connects the input fabric, local fabric, output fabric, internal
registers, data accelerator, mailbox, CPU wrapper, interrupt aggregation, and
debug bus.

Important RTL connections to preserve:

* CPU MMIO master feeds the fabric input path (`axi_in_mmio_req_i`).
* System ingress goes through inbound filters before local-fabric access.
* SEP ingress is remapped to the local fabric path and bypasses the inbound
  filter in the SystemC LT model.
* Local decode fans out to front port, data-accelerator control, consolidated
  peripherals, DFD/APB, base-config, remap/filter CSRs, mailbox, and DFT CSR.
* Outbound traffic passes through output remap and outbound filters before
  `output_axi`.
* Interrupts are composed into the CPU interrupt vector before they reach the
  generated CPU wrapper.

=== CPU Boundary: `smc_cpu_wrapper.sv`

The RTL CPU wrapper demuxes the local-fabric front port:

* addresses in `SMC_CPU_CTRL_REG_MAP_BASE_ADDR..+SIZE` go to
  `smc_cpu_ctrl_wrap`,
* all other front-port traffic goes to the generated CPU L2 frontend,
* the generated CPU exposes an MMIO AXI master back to the fabric,
* ROM and scratch RAM are attached through generated memory interfaces,
* CPU reset, reset vector, uncore reset, debug reset, isolate request, drained
  status, WDT, DED, and writeback PC are controlled or observed by
  `smc_cpu_ctrl_wrap`.

The SystemC `smc_cpu_cluster` combines the CPU execution model and the CPU
control register target. A top-level SystemC platform should route the fabric
front-port CPU-control window to `cluster.ctrl`, and route the cluster `mmio`
initiator back into `smc_fabric.mmio_in`.

== Fabric Integration

=== Recommended TLM Topology

[source,text]
----
external sys master  -> smc_fabric.sys_axi_in  -> local or output path
external JTAG master -> smc_fabric.jtag_axi_in -> local or output path
SEP master           -> smc_fabric.sep_axi_in  -> local path
CPU cluster mmio     -> smc_fabric.mmio_in     -> local or output path
data accelerator     -> smc_fabric.data_accel_in
log engine           -> smc_fabric.log_in

smc_fabric.to_front_port      -> CPU-control router / CPU L2 frontend target
smc_fabric.to_data_accel_ctrl -> DMA/zeroer control stub or model
smc_fabric.to_periph          -> SMC peripheral xbar/router
smc_fabric.to_dfd_apb         -> DFD/CLA stub or model
smc_fabric.to_cpu_ctrl        -> smc_cpu_cluster.ctrl
smc_fabric.to_mailbox         -> mailbox stub or model
smc_fabric.to_dft_csr         -> DFT/DTP stub or model
smc_fabric.output_axi         -> platform/system memory or NoC model
----

The existing `smc_fabric` model already owns base-config, remap, and filter
CSR behavior. Bind stubs to unused fabric initiator sockets so tests can catch
unexpected traffic and so firmware sees deterministic behavior.

=== Local Decode Considerations

The fabric model's local decode mirrors the RTL crossbar route classes rather
than every final peripheral subwindow. It routes the peripheral main aperture
and peripheral extension aperture to `to_periph`; a SystemC SMC peripheral
router should then decode the detailed `smc_top_reg.svh` peripheral subwindows.

The CPU-control address is a common source of confusion:

* `0xC001_0000` is `SMC_BASE_CONFIG`, owned by fabric.
* `0xC003_9000` is `SMC_CPU_CTRL`, routed to CPU control.

Route `0xC003_9000..0xC003_92BF` to `smc_cpu_cluster.ctrl`, not to the
base-config CSR handler.

=== Interrupt Binding

The SystemC CPU cluster has three per-hart inputs:

* `irq_sw[h]` from CLINT `msip_o[h]`,
* `irq_timer[h]` from CLINT `mtip_o[h]`,
* `irq_ext[h]` from the PLIC context output for M-mode context `h`.

For 4-core SMC, PLIC contexts are:

[cols="15,20,20,45",options="header"]
|===
|Context |Hart |Privilege |Typical SystemC binding
|0 |0 |M-mode |`plic.ctx_out[0] -> cluster.irq_ext[0]`
|1 |1 |M-mode |`plic.ctx_out[1] -> cluster.irq_ext[1]`
|2 |2 |M-mode |`plic.ctx_out[2] -> cluster.irq_ext[2]`
|3 |3 |M-mode |`plic.ctx_out[3] -> cluster.irq_ext[3]`
|4..7 |0..3 |S-mode |Bind when S-mode firmware is modeled; otherwise leave deasserted/stubbed.
|===

The PLIC source inputs are the raw CPU interrupt vector bits plus one as a PLIC
source ID. Source 0 is reserved.

=== ROM and Scratchpad

For RTL parity, configure:

[source,cpp]
----
broker.set_preset_cci_value("top.bootrom.size_bytes",
                            cci::cci_value(uint64_t(0x20000)));
broker.set_preset_cci_value("top.scratchpad_ram.size_bytes",
                            cci::cci_value(uint64_t(0x100000)));
broker.set_preset_cci_value("top.cluster.reset_pc",
                            cci::cci_value(uint64_t(0xC0040000)));
----

The `bootrom` model accepts 1/2/4/8-byte naturally aligned reads and ignores
writes. The `scratchpad_ram` model accepts 1/2/4/8-byte reads and writes,
honors byte enables, and can preload data. Use ELF-section loading in the
platform if firmware expects initialized `.data` in SRAM while executing text
from ROM.

== Peripheral Subsystem Integration

The RTL `smc_peripherals.sv` receives one consolidated AXI-Lite slave from the
local fabric, then `smc_periph_axi_lite_xbar` fans out to peripheral blocks.
The SystemC equivalent should be a lightweight TLM router bound to
`smc_fabric.to_periph`.

=== Modeled Blocks

==== Reset Unit

Bind the reset-unit register aperture at `0xC000_2000` to
`reset_unit.reg_socket`, subtracting the base before forwarding. Wire:

* `powergood_i`, `rst_cold_ni`, `fuse_reset_ni`, `rst_ext_wdt_ni`,
  `rst_cool_ni`, `cfg_flr_pf_active_i`, `isolate_req_pin_i`,
  `ss_reset_complete_i`, and `captured_straps_i`,
* reset outputs to the platform reset signals used by CPU, fabric, memories,
  and peripherals,
* `sync_irq_o` into the external/system interrupt path if firmware observes it,
* `isolate_req_o`, `ss_config_o`, and `ss_reset_ctrl_o[]` to platform signals
  or monitors.

The model abstracts reset synchronizer latency and deglitch counters but keeps
the functional reset derivation, FLR cool reset flow, lock behavior, and reset
domains.

==== UART

RTL has `NUM_UART = 4` and instantiates `uart_wrap` with log engines enabled.
The current SystemC `uart` model represents one 16550-style UART. For SMC
integration:

* instantiate four UART models or wrap one model in a four-instance aperture,
* decode the `SMC_UART_WRAP` subwindows under `0xC000_A000`,
* bind each UART interrupt into the combined UART/log interrupt source that
  eventually drives peripheral interrupt bits 21:18,
* tie unused modem inputs high (`dsr_ni`, `ri_ni`, `dcd_ni`) to match RTL,
* route `rx_i`, `tx_o`, RTS/CTS, DMA-ready, error, and interrupt sidebands to
  a console, loopback, or testbench harness.

The log engine registers are connected in RTL but do not have an SMC SystemC
model. If firmware touches them before a model exists, provide a reset-value
stub and a clear diagnostic.

==== I3C

RTL currently connects an `i3ccore_stub` at `OCA_I3C_WRAP_0_REG_MAP_BASE_ADDR`
with:

* `NUM_I3C = 6`,
* instance spacing from `i3ccore_wrap_pkg::I3C_INSTANCE_SPACING`,
* AXI-Lite request/response through the peripheral CDC path,
* per-instance interrupts to `i3c_irqs_periph_clk`,
* SCL/SDA/OE/open-drain/push-pull signals to the padring,
* DAT/DCT memory interfaces.

The SystemC `i3c_controller` is more functional than the current RTL stub. It
models the six-instance HCI/PIO register space, command/response/TX/RX/IBI
queues, a transaction-level bus callback, and per-instance IRQs. Bind its
single `reg_socket` to the I3C aperture and connect:

* `irq_o[0..5]` to peripheral interrupt bits 17:12 after synchronization,
* SCL/SDA outputs to an abstract bus/pad harness,
* `set_bus_model(inst, callback)` for target behavior,
* `inject_ibi()` for target-originated IBI tests.

Document in tests that RTL is connected as a stub today, while SystemC can be
used as the intended functional model for firmware bring-up.

==== PLIC

Bind `0xC400_0000` to `plic.reg_socket`. Configure:

* `num_sources = 336` for current 4-core default,
* `num_contexts = 8` for four harts with M/S contexts,
* source inputs from the CPU interrupt vector composition,
* M-mode context outputs to `smc_cpu_cluster.irq_ext[h]`.

The model implements rising-edge pending latches, priority/threshold
arbitration, claim/complete side effects, and level-sensitive re-pend on
completion if the source line remains high.

==== CLINT

Bind `0xC800_0000` to `clint.reg_socket`. Configure `num_harts` to match the
cluster and choose `tick_period_ns` to match firmware expectations. Connect:

* `msip_o[h] -> cluster.irq_sw[h]`,
* `mtip_o[h] -> cluster.irq_timer[h]`,
* `rst_n_i` to the primary/core reset policy.

The model supports 32-bit halves and 64-bit accesses for `MTIME` and
`MTIMECMP`.

==== Boot ROM and Scratchpad RAM

Although RTL connects ROM and scratch RAM through generated memory macro
interfaces rather than AXI-Lite peripheral registers, the SystemC models expose
TLM targets. Bind them through the front-port/local memory decode:

* `0xC004_0000..0xC005_FFFF` to `bootrom.reg_socket`,
* `0xC006_0000..0xC015_FFFF` to `scratchpad_ram.reg_socket`.

If the top-level platform also supports direct CPU fast memory, disable or
avoid overlapping fast-memory windows for these regions to keep all firmware
access visible to the integration fabric.

|Watchdog timers
|CPU cluster WDT windows at `0xC000_0000 + core*0x400`
|`wdt_first_timeout_o`, `wdt_second_timeout_o`, reset-unit WDT input
|Return reset values; optionally expose a test API to force first/second
timeout.

|RISC-V debug module
|`0xC000_1000`, CPU JTAG signals
|Debug reset and JTAG TDO
|Map to CPU-cluster debug API where possible; otherwise return benign reset
values.

|SMC misc wrapper
|`smc_misc_wrap`, scratch/chip config/NDM/RAS/lifecycle
|NDM reset request/process, RAS bank outputs
|Implement early if firmware uses scratch/status. Use `regmodel` for scratch
registers and expose deterministic lifecycle/chip config values.

|PLL wrapper
|Top-level AXI-Lite shim port
|Clock observation signals
|Return locked/success reset values needed by ROM until a PLL model exists.

|GPIO/padring
|`smc_padring`, GPIO control, strap capture, protocol muxing
|GPIO interrupts bits 29 and 30, boot stall, cool reset pin
|Provide strap inputs, boot-stall control, and GPIO interrupt forcing APIs.

|PVT
|Top-level AXI-Lite shim port
|`temp_interrupt_i` to peripheral bit 27
|Return stable sensor/status values; allow temperature interrupt injection.

|AVSBus
|`avsbus_controller`
|Peripheral bit 22, debug state
|Return idle/done status for ROM; allow interrupt forcing for tests.

|I2C
|`i2c_wrap`, 3 instances, pad mux and CDC
|Peripheral bits 25:23
|Stub reset values for early boot; develop target/controller model before OCCP
over I2C tests.

|Log engine
|Inside `uart_wrap`, one per UART
|Combined into UART/log interrupt bits 21:18
|Return FIFO-empty/idle status; optionally forward log fetches to a console.

|eFuse
|`smc_efuse_wrapper`, shadow regs, JTAG AXI-Lite, shim command interface
|`fuse_sense_done_o`, `fuse_reset_n_o`, locked-field interrupt bit 28
|High priority for ROM boot. Provide deterministic shadow-register preload,
lifecycle/security responses, and fuse-sense completion.

|Telemetry receiver
|`telemetry_receiver_wrap`, 3 receivers
|Peripheral bits 10:8
|Return idle status; optional ATB packet injection later.

|System Timer OCTS
|`system_timer_octs`, primary/secondary sync through padring
|`timer_count_o`
|Provide monotonically increasing 64-bit timer and stable role-dependent sync
status.

|Mailbox
|32 channels at `0xC001_8000`
|Mailbox vector inserted after peripheral interrupts
|Implement FIFO/register model before cross-processor firmware tests. Stub
should expose empty/not-full status and controlled IRQ injection.

|DMA controller
|Data accelerator frontend/backend
|Internal interrupt 2
|Stub status/done registers or implement descriptor-level memory copy.

|Zeroer
|Data accelerator zeroer control at `0xC003_8200`
|Internal interrupt 3
|Stub as instant success or implement a TLM memory-zero transaction against
scratch/system memory.

|DFD/CLA/DTP/DFT
|DFD APB, DTP CSR external port, CLA actions/trace memory
|Internal CLA/TDR interrupts and debug bus
|Return reset values unless debug firmware requires more detail.

|Bus Error Units
|Four BEU windows at `0xC801_0000 + core*0x1000`
|May feed PLIC depending enables
|Stub cause/address/enable registers; later connect to TLM decode or response
errors.

|Adopter extension
|AXI-Lite extension port from peripheral xbar
|Platform-specific
|Bind to an externally supplied target or default error/RAZ-WI stub.
|===

== Interrupt Composition

RTL builds `cpu_interrupts_o` in `smc_base.sv`:

[source,text]
----
cpu_interrupts_o[NUM_EXT_INTERRUPTS-1:0]        = ext_interrupts_i
cpu_interrupts_o[NUM_EXT_INTERRUPTS+:32]        = peripheral_interrupts_i
cpu_interrupts_o[(NUM_EXT_INTERRUPTS+32)+:32]   = mailbox_interrupts
cpu_interrupts_o[(NUM_EXT_INTERRUPTS+64)]       = TDR clock-stop interrupt
cpu_interrupts_o[(NUM_EXT_INTERRUPTS+64)+1]     = CLA interrupt
cpu_interrupts_o[(NUM_EXT_INTERRUPTS+64)+2]     = DMA interrupt
cpu_interrupts_o[(NUM_EXT_INTERRUPTS+64)+3]     = zeroer interrupt
----

`NUM_EXT_INTERRUPTS` is CPU-config dependent:

[cols="20,20,30,30",options="header"]
|===
|Config |Harts |External bits |Total CPU interrupt bits
|`SMC_1CORE` |1 |32 |104
|`SMC_4CORE` |4 |256 |328
|===

RTL builds the 32-bit `peripheral_interrupts_o` in `smc_peripherals.sv`:

[cols="18,42,40",options="header"]
|===
|Bit(s) |RTL source |SystemC source
|7:0 |`sep_mailbox_interrupts_i` |Top-level input or mailbox/SEP stub
|10:8 |`telemetry_irq` |Telemetry stub/model
|11 |OR of `ndmreset_request_smc_clk` |SMC misc/NDM stub
|17:12 |`i3c_irqs_smc_clk` |`i3c_controller.irq_o[5:0]`
|21:18 |`uart_irq_combined_smc_clk` |UART/log wrapper interrupt combine
|22 |`avsbus_irq_smc_clk` |AVSBus stub/model
|25:23 |`i2c_irqs_smc_clk` |I2C stub/model
|26 |Synchronized active-high SEP WDT reset assertion |Top-level SEP WDT input
|27 |`temp_interrupt_smc_clk` |PVT/temp input or stub
|28 |`locked_field_access_interrupt` |eFuse/security model
|29 |OR of lower half GPIO interrupts |GPIO/padring model
|30 |OR of upper half GPIO interrupts |GPIO/padring model
|31 |Unused in current RTL composition |Tie low unless RTL changes
|===

Feed these raw interrupt bits into PLIC source lines with source ID equal to
bit index + 1. CLINT MSIP/MTIP bypass the PLIC and connect directly to the CPU
cluster interrupt inputs.

== Reset and Clock Integration

The SystemC platform should preserve reset ordering and observable effects, not
cycle-level synchronizer behavior.

* Use `reset_unit` as the owner of derived reset signals whenever the reset
  unit model is present.
* Drive fabric and peripheral reset inputs from reset-unit primary reset.
* Drive CPU reset/run state through `smc_cpu_cluster.ctrl` and/or platform glue
  that mirrors `smc_cpu_ctrl_wrap`.
* Model boot stall as a sticky hold that can deassert once after primary reset,
  matching `smc_peripherals.sv`.
* Keep `fuse_reset_n`/`fuse_sense_done` controlled by the eFuse stub/model so
  ROM boot does not start before eFuse defaults are available.
* Treat clock gates as enable/status bits unless firmware explicitly depends on
  a gated-clock side effect. Do not build separate SystemC clock domains unless
  needed for behavior.

== Suggested `smc_platform` Structure

[source,cpp]
----
class smc_platform : public sc_core::sc_module {
public:
    tlm_utils::simple_target_socket<smc_platform, 64> sys_axi_in{"sys_axi_in"};
    tlm_utils::simple_target_socket<smc_platform, 64> jtag_axi_in{"jtag_axi_in"};
    tlm_utils::simple_target_socket<smc_platform, 64> sep_axi_in{"sep_axi_in"};
    tlm_utils::simple_initiator_socket<smc_platform, 64> output_axi{"output_axi"};

    smc::smc_fabric fabric{"fabric"};
    smc::smc_cpu_cluster cluster{"cluster"};
    smc::reset_unit reset{"reset"};
    smc::plic plic{"plic"};
    smc::clint clint{"clint"};
    smc::bootrom bootrom{"bootrom"};
    smc::scratchpad_ram scratch{"scratchpad_ram"};

    // Add wrappers/routers:
    // - periph_router: reset, misc, GPIO, I3C, PVT, AVS, I2C, UART, eFuse,
    //   telemetry, OCTS, DTP, extension.
    // - front_port_router: CPU control, ROM, scratch, PLIC, CLINT, BEU, CPU L2.
    // - interrupt_aggregator: peripheral/mailbox/internal vector into PLIC.
};
----

Recommended routers:

* `periph_router`: 32-bit AXI-Lite-style TLM target bound to
  `fabric.to_periph`; subtracts block base before forwarding to modeled
  peripherals.
* `front_port_router`: 64-bit TLM target bound to `fabric.to_front_port`;
  routes CPU control, ROM, scratch, PLIC, CLINT, and BEU.
* `stub_target`: reusable target with configurable reset values, RAZ/WI
  behavior, optional sticky warning, and optional interrupt output.
* `interrupt_aggregator`: SC_METHOD that composes external, peripheral,
  mailbox, and internal sources, then drives `plic.src_in[]`.

For the eventual SMC platform test, add milestones in this order:

1. Platform elaborates with CCI broker presets and all sockets bound.
2. CPU reset vector is `0xC004_0000`.
3. CPU fetches ROM bytes through `bootrom`.
4. CPU reads/writes scratchpad at `0xC006_0000`.
5. Reset-unit and misc/strap/eFuse stubs provide deterministic early boot
   values.
6. CLINT MSIP/MTIP and PLIC external interrupt wake a hart.
7. UART console output works through a modeled UART instance.
8. Production or smoke ROM reaches the first known status/post-code milestone.
9. Replace stubs with functional models in firmware touch order.
