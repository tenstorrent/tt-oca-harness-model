[[i3c-controller-implementation]]
===== SystemC/TLM-2.0 Implementation

`smc::i3c_controller` is a loosely-timed TLM-2.0 model of the
multi-instance OCA I3C HCI. Timing is annotated `access_delay_ns` plus
`xfer_delay_ns` from command enqueue to response. Bit-level SCL/SDA and
OD/PP timing are not modelled. `b_transport` never calls `wait()`. DMI
is never granted.

[source,cpp]
----
class i3c_controller : public sc_core::sc_module
----

The single `reg_socket` carries `num_instances × INSTANCE_SPACING`.
Decode is `inst = addr / spacing`, `loff = addr % spacing`, matching
the RTL AXI-Lite demux.

====== Threads and sockets

`output_method` is the sole writer of every per-instance `sc_out`.
`xfer_method` pops one pending instance, runs `process_command`, and
re-notifies while `xfer_pending_` is non-empty. Bus and recovery pins
are held idle.

With `HC_CONTROL.BUS_ENABLE`, a completed 64-bit COMMAND_PORT
descriptor schedules a transfer. The engine resolves the dynamic
address from DAT, calls `bus_model_fn`, drains/fills TX/RX, and pushes
a response. No bus model means address NACK. Because this LT model has no
pin-level SDA event interface, `inject_ibi` is the production external-target
adapter for an in-band interrupt; it enqueues the IBI status and payload that
firmware consumes through `IBI_PORT`.

`smc-vp` binds the one `reg_socket` on the peripheral router for the
whole I3C aperture (`NUM_I3C` = 6). Per-instance `irq_o[i]` enters the
interrupt aggregator. Instance 0 gets an echo bus model for
`smc-i3c-loopback-test`.

====== CCI parameters

Instance count and FIFO depths are immutable. Delays are mutable.

[cols="36%,20%,44%",options="header"]
|===
|Parameter |Default |Use
|`num_instances` |6 |Instances (1..6); sizes `sc_vector` ports
|`access_delay_ns` |2.0 |Annotated TLM access delay
|`xfer_delay_ns` |100.0 |Enqueue-to-response latency
|`cmd_fifo_depth` |8 |Command/response entries
|`rx_fifo_depth` |64 |RX DWORDs
|`tx_fifo_depth` |64 |TX DWORDs
|`ibi_fifo_depth` |8 |IBI DWORDs
|===

`num_instances` outside 1..6, a negative delay, or a zero FIFO depth is
`SC_REPORT_FATAL`.

Both delays are re-read from CCI at the point of use — `access_delay_ns`
in `b_transport`, `xfer_delay_ns` in `schedule_xfer()` — so a run-time
change takes effect on the next access or the next enqueued command.
Caching either at construction would make the documented mutability a
lie.

====== Bus contract

[cols="28%,72%",options="header"]
|===
|Aspect |Contract
|Size / alignment
|Naturally aligned 32-bit accesses only; anything else is
 `TLM_BURST_ERROR_RESPONSE`.
|Decode
|Instance from `addr / INSTANCE_SPACING`, offset from the remainder.
 Out of aperture is an address error; an unimplemented offset *inside*
 an instance window is RAZ/WI, not a fault, so decode cannot miss once
 the aperture check has passed.
|Byte enables
|Any non-null `byte_enable_ptr` is refused whatever its length,
 including the zero-length and all-lanes-enabled forms.
|Streaming width
|Single beat, so TLM-2.0 requires `streaming_width >= data_length`.
 Larger is accepted and ignored, matching the sibling SMC models.
|Debug / DMI
|`transport_dbg` serves the DAT/DCT windows only — never a FIFO port —
 and refuses anything that is neither a read nor a write. DMI is always
 denied and `dmi_allowed` is cleared on every transaction.
|Sideband
|The canonical `smc::smc_axi_extension` is inspected for tracing and
 left untouched; authorization belongs to the fabric's `axi_filter`.
|===

====== Command attribute legality

Only `CMD_ATTR = 0` (regular transfer) is executed. HCI also defines
immediate-data, address-assignment, combo and internal-control
attributes; the model reports `NotSupported` for those rather than
running them as a regular transfer, and rejects them before the TX FIFO
is touched so a malformed descriptor cannot consume a later command's
payload.

====== Modeling gaps versus RTL

* SCL/SDA and OD/PP pins stay idle; data movement is the bus-model
  callback.
* PHY CDC synchronisers are not modelled.
* Only the CSR-visible DAT/DCT windows are modelled (32 / 16 entries).
  The RTL external 128-entry `dat_mem` / `dct_mem` tables are not.
* HDR modes, TCRI recovery datapath, and scan/DFT are not modelled.
  Recovery outputs stay idle.
* `INTR_STATUS_ENABLE` gates nothing: `irq_o` follows signal-enable
  alone and status bits latch regardless. Needs HCI confirmation.
* A short read always completes with `Success` and the actual length;
  `i3c_err::I3cShortReadErr` is never produced because no modelled
  command-descriptor flag selects that policy. Needs confirmation.
* The response descriptor's DATA_LENGTH is 12 bits while the command's
  is 16, so a transfer of 0x1000 bytes or more cannot report its true
  length. Whether the HC should reject such a command is unresolved.
