[[i3c-controller-test-plan]]
===== Test Plan

====== Standalone bench

Three benches in `test/`, and the split between them is load bearing:

* `i3c_controller_tb` — *architectural*. A 3-instance DUT with a bus
  model for one target at dynamic address `0x42`. Drives the model only
  through its TLM socket and its output signals. Only these cases may be
  cited as evidence of HCI/TLM behaviour.
* `i3c_controller_neg_tb` — *architectural, negative*. Constructor
  fatals, the malformed-payload matrix, `transport_dbg` refusals and DMI
  policy, all without `sc_start`.
* `i3c_controller_cov_tb` — *structural*. Coverage-completion cases that
  reach debug entry points (`dbg_read`, `dump_state`, out-of-range
  `set_bus_model`/`inject_ibi`) and internal branches with no externally
  observable HCI meaning. Useful, but not conformance evidence.

The architectural register cases check the model against an independent
CSR manifest (`kCsrs` in the primary bench) — a second transcription of
the I3CCSR map giving each register's reset value and its read-back
after an all-ones write. It is deliberately not derived from the model's
switch statements, so a slip on either side fails the sweep.

Success: all three benches print `ALL TESTS PASSED`; CTest reports 3/3;
`--asan` produces no sanitizer log; the model source and header each meet
the repository >= 95% line gate individually.

How to run (from `smc/peripherals/i3c_controller`):

[source,bash]
----
./run_tests.sh                # Release build + run all three benches
./run_tests.sh --ctest
./run_tests.sh --asan         # AddressSanitizer + UndefinedBehaviorSanitizer
./run_tests.sh --coverage     # isolated build_cov/; do not combine with --asan
./run_tests.sh --ubsan-canary # proves the UBSan gate can actually fail
./run_tests.sh --clean

cd smc
./run_all_smc_tests.sh i3c_controller
----

`run_tests.sh` probes `SYSTEMC_HOME` / `CCI_HOME`.

====== Build and sanitizer gates

[cols="30%,70%",options="header"]
|===
|Gate |Requirement
|Auxiliary bench exits
|The runner records the exit status of all three benches and fails if any
 is non-zero, in the plain and sanitizer paths alike.
|Per-file coverage
|`--coverage` sets `COVERAGE_PER_FILE=1`, so `src/` and the inline
 behaviour in `include/` are each gated at >= 95% on their own.
|Sanitizers
|`--asan` builds with AddressSanitizer *and* UndefinedBehaviorSanitizer
 and fails on any report.
|UBSan canary
|`--ubsan-canary` compiles a deliberate shift overflow into the
 *negative* bench, so the mode proves both that UBSan reports and that
 the runner propagates an auxiliary bench's failure.
|===

====== Open spec questions

Pinned by test so that changing them is a deliberate, reviewed decision,
but each needs confirming against the RDL / HCI specification:

* *INTR_STATUS_ENABLE does not gate anything.* `irq_o` is driven by
  signal-enable alone and the status bit latches regardless of either
  enable. HCI implementations differ on whether status-enable gates
  latching.
* *Short reads always succeed.* `i3c_err::I3cShortReadErr` exists for
  "short read not permitted", but no modelled command-descriptor flag
  selects that policy.
* *Response DATA_LENGTH truncates to 12 bits.* The command descriptor's
  length field is 16 bits, so a transfer of 0x1000 bytes or more cannot
  report its true length. Whether the HC should instead reject such a
  command is unresolved.

====== Platform firmware tests

These run on `smc-vp` with a RISC-V bare-metal toolchain. Build the VP
first (`make smc-vp` from the repo root after `vp/configure_vp.sh`).

[source,bash]
----
cd sw/smc-vp-tests
./run_smc_vp_tests.sh smc-i3c-loopback-test
----

`smc-i3c-loopback-test` uses the instance-0 echo bus model on `smc-vp`.
There is no separate `smc-i3c-test` directory.
