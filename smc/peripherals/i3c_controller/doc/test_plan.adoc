[[i3c-controller-test-plan]]
===== Test Plan

====== Standalone bench

`i3c_controller_tb` and `i3c_controller_neg_tb` (`test/`). The primary
bench uses a 3-instance DUT and a bus model for one target at dynamic
address `0x42`. The negative bench probes constructor fatals without
`sc_start`.

Success: both benches print `ALL TESTS PASSED`; CTest reports 2/2;
`--asan` produces no `asan.log.*`.

How to run (from `smc/peripherals/i3c_controller`):

[source,bash]
----
./run_tests.sh              # Release build + run both benches
./run_tests.sh --ctest
./run_tests.sh --asan
./run_tests.sh --coverage   # isolated build_cov/; do not combine with --asan
./run_tests.sh --clean

cd smc
./run_all_smc_tests.sh i3c_controller
----

`run_tests.sh` probes `SYSTEMC_HOME` / `CCI_HOME`.

|5 |Private write |TX + command → SUCCESS; bus sees LE bytes |Positive

====== Platform firmware tests

These run on `smc-vp` with a RISC-V bare-metal toolchain. Build the VP
first (`make smc-vp` from the repo root after `vp/configure_vp.sh`).

[source,bash]
----
cd sw/smc-vp-tests
./run_smc_vp_tests.sh smc-i3c-loopback-test
./run_smc_vp_tests.sh smc-i3c-test
----

`smc-i3c-loopback-test` uses the instance-0 echo bus model on `smc-vp`.
`smc-i3c-test` is HCI_VERSION / HC_CONTROL / PIO_CONTROL;
`sw/smc-vp-tests/README.md` currently lists that directory as
documented but not present in the tree.
