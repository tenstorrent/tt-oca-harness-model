[[i2c-controller-test-plan]]
===== Test Plan

====== Standalone bench

`i2c_controller_tb` and `i2c_controller_neg_tb` (`test/`) drive
`reg_socket`, `rst_n_i`, a bus-model callback, and the target back
doors. The primary bench uses a live kernel; the negative bench probes
constructor fatals without `sc_start`.

Success: both benches print `ALL TESTS PASSED`; CTest reports 2/2;
`--asan` produces no `asan.log.*`. Line coverage of
`src/i2c_controller.cpp` is ~99% in the existing plan.

How to run (from `smc/peripherals/i2c_controller`):

[source,bash]
----
./run_tests.sh              # Release build + run both benches
./run_tests.sh --ctest
./run_tests.sh --asan
./run_tests.sh --coverage   # isolated build_cov/; do not combine with --asan
./run_tests.sh --clean

cd smc
./run_all_smc_tests.sh i2c_controller
----

`run_tests.sh` probes `SYSTEMC_HOME` / `CCI_HOME`.

====== Platform firmware tests

These run on `smc-vp` with a RISC-V bare-metal toolchain. Build the VP
first (`make smc-vp` from the repo root after `vp/configure_vp.sh`).

[source,bash]
----
cd sw/smc-vp-tests
./run_smc_vp_tests.sh smc-i2c-loopback-test
----

`smc-i2c-loopback-test` uses the I2C0→I2C1 bus-model bind on `smc-vp`.
There is no separate `smc-i2c-test` directory.
