[[uart-implementation]]
===== SystemC/TLM-2.0 Implementation

`smc::uart` is a loosely-timed TLM-2.0 model of one NS16550A-compatible
UART. Timing is annotated `access_delay_ns`, not bit-level serial
timing. TX/RX are character-granularity. `b_transport` never calls
`wait()`; the quantum keeper is the initiator's. DMI is never granted
(RBR/IIR/MSR reads have side effects).

[source,cpp]
----
class uart : public sc_core::sc_module
----

SCR / ECR / ITR use the shared `regmodel::Register8` map. DLAB-banked
and side-effect registers stay in `reg_read` / `reg_write`.

====== Threads and sockets

`reset_proc` clears state. `modem_method` samples CTS/DSR/RI/DCD and
sets MSR deltas. `rx_timeout_method` raises the RX-timeout interrupt
after a coarse functional delay. `recompute_method` is the sole writer
of every `sc_out` (`update_outputs()`). State-changing paths call
`schedule_recompute()`.

THR writes push and functionally drain the TX FIFO in one recompute.
RX arrives through `inject_rx_char()` or system loopback. Line loopback
(`MCR.LINE_LOOP`) takes precedence over system loopback (`MCR.LOOP`).
Baud divisor 0 disables TX and RX.

`smc-vp` instantiates `NUM_UART` (4) copies. The peripheral router binds
each `reg_socket` at the TRM 16550 window. `irq_o` enters the interrupt
aggregator; modem inputs are tied idle (`rx` high, `cts` asserted,
`dsr`/`ri`/`dcd` high). `uart_[0]` can feed the platform console via
`dbg_tx_pop()`.

                                    │
                         recompute_method ──► irq / DMA / modem outs
----

====== CCI parameters

FIFO depths are immutable after construction. `access_delay_ns` is
re-read on every transaction.

[cols="36%,20%,44%",options="header"]
|===
|Parameter |Default |Use
|`tx_fifo_depth` |32 |TX FIFO bytes (1..4096)
|`rx_fifo_depth` |32 |RX FIFO bytes (1..4096)
|`access_delay_ns` |2.0 |Annotated TLM access delay
|===


====== Bus contract (both targets)

`uart` and `uart_wrap` share one `check_csr_access()` helper, so neither can
drift from the other.

[cols="28%,72%",options="header"]
|===
|Aspect |Contract
|Command
|Only read and write; anything else is `TLM_COMMAND_ERROR_RESPONSE`.
|Pointer / length
|A null `data_ptr` or zero length is `TLM_GENERIC_ERROR_RESPONSE`. This is
 load bearing: both targets `memcpy` through the pointer, so without the
 check a null-pointer transaction segfaults the simulator.
|Size / alignment
|Naturally aligned 32-bit accesses only.
|Decode
|Overflow-safe window bound (`len > window - adr`), never
 `adr + len > window`, which wraps near `UINT64_MAX`. An unmapped offset
 *inside* the window differs by target: `uart` reports a decode miss,
 `uart_wrap` is RAZ/WI.
|Byte enables
|Any non-null `byte_enable_ptr` is refused whatever its length.
|Streaming width
|Single beat, so TLM-2.0 requires `streaming_width >= data_length`.
|DMI
|Always denied, and `dmi_allowed` is cleared before any early return: RBR
 pops the FIFO, IIR/LSR/MSR reads clear status, THR transmits, and writing
 LOG_EN resets the wrapper's log engine.
|Sideband
|The canonical `smc::smc_axi_extension` is inspected for tracing and left
 untouched; authorization belongs to the fabric's `axi_filter`.
|===

====== Debug transfer contract

Deliberately asymmetric, and tested as such:

* A debug *read* is side-effect-free. It goes through `dbg_reg()`, so it
  never pops RBR, clears IIR/LSR/MSR status, or rearms the RX timeout.
* A debug *write* uses the same path as a software write, so a debugger can
  program the device.

====== RX character timeout

The timeout restarts on the most recent of "character received" and "RBR
read", per the 16550 contract, and is disarmed when the FIFO drains.
Clearing only the pending flag on an RBR read (as an earlier revision did)
left the timer running from the previous arrival, so a multi-character read
could time out almost immediately after a read rather than one idle period
later.

====== Modeling gaps versus RTL

* No bit-level serialisation. Baud rate only disables TX/RX when the
  divisor is 0. Two models cannot handshake at a real baud rate.
* RX timeout is a coarse `sc_event`, not 4 character-times.
* No noise/glitch filter or input synchronisers.
* TX FIFO drains in one recompute (LT: software always sees consistent
  THRE/TEMT after its write).

* `uart_wrap` is a CSR shell: the log region/write-address/entry registers
  have no log-engine datapath behind them and the log interrupt pair drives
  no output port. Needs the RDL owner to define the datapath.
