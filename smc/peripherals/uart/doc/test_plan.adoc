[[uart-test-plan]]
===== Test Plan

====== Standalone bench

`uart_tb` (`test/uart_tb.cpp`) is a TLM initiator into the register
window plus `rst_n_i`, modem pins, and `inject_rx_char` / `dbg_tx_pop`
/ `dbg_reg` helpers. No serial line is required.

Success: the bench prints `ALL TESTS PASSED`; `--asan` produces no
`asan.log.*`.

How to run (from `smc/peripherals/uart`):

[source,bash]
----
./run_tests.sh              # Release build + run
./run_tests.sh --ctest
./run_tests.sh --asan
./run_tests.sh --coverage   # isolated build_cov/; do not combine with --asan
./run_tests.sh --clean

cd smc
./run_all_smc_tests.sh uart
----

`run_tests.sh` probes `SYSTEMC_HOME` / `CCI_HOME`. A local `deps.env`
overrides those paths.

====== Known modelling gap

`uart_wrap` is a CSR shell: the log-region, write-address and 16 entry
registers have no logging datapath behind them, and the log interrupt
status/enable pair drives no output port. The bench proves the CSR
contract exhaustively and nothing more. Implementing the log engine
(audit finding 4 / UART-WRAP-002) needs the RDL owner to define the
datapath; it is deliberately not invented here.

====== Platform firmware tests

There is no `smc-uart-test` in `sw/smc-vp-tests/`. UART0 is the firmware
`printf` path for the tests that are present; register coverage is the
standalone `./run_tests.sh` suite in this directory.
