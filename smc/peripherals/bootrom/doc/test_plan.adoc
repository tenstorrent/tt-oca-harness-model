[[bootrom-test-plan]]
===== Test Plan

====== Standalone bench

`bootrom_tb` (hex fixture), `bootrom_bin_tb` (`.img` fixture), and
`bootrom_neg_tb` (`test/`). The negative bench probes constructor
fatals without `sc_start`. There is no committed `03_BOOTROM_Test_Plan.md`
in this tree; cases below come from the benches and the README.

Success: benches print `ALL TESTS PASSED`; `--asan` produces no
`asan.log.*`.

How to run (from `smc/peripherals/bootrom`):

[source,bash]
----
./run_tests.sh              # Release build + run benches
./run_tests.sh --ctest
./run_tests.sh --asan
./run_tests.sh --coverage   # isolated build_cov/; do not combine with --asan
./run_tests.sh --clean

cd smc
./run_all_smc_tests.sh bootrom
----

`run_tests.sh` probes `SYSTEMC_HOME` / `CCI_HOME`.

====== Platform firmware tests

There is no `smc-bootrom-test` in `sw/smc-vp-tests/`. Boot ROM coverage
is the standalone `./run_tests.sh` suite in this directory. `smc-vp`
preloads the ROM image; firmware that fetches from it is exercised
indirectly by the tests that are present.
