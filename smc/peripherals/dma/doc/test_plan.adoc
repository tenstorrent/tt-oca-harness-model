[[dma-test-plan]]
===== Test Plan

====== Standalone bench

`dma_tb` and `dma_neg_tb` (`test/`). The primary bench binds
`reg_socket` to a probe initiator and `mst_socket` to a simple memory
target. The negative bench probes constructor fatals and TLM errors.

Success: both benches print `ALL TESTS PASSED`; CTest reports 2/2;
`--asan` produces no `asan.log.*`.

How to run (from `smc/peripherals/dma`):

[source,bash]
----
./run_tests.sh              # Release build + run both benches
./run_tests.sh --ctest
./run_tests.sh --asan
./run_tests.sh --coverage   # isolated build_cov/; do not combine with --asan
./run_tests.sh --clean

cd smc
./run_all_smc_tests.sh dma
----

`run_tests.sh` probes `SYSTEMC_HOME` / `CCI_HOME`. A local `deps.env`
overrides those paths.

====== Platform firmware tests

These run on `smc-vp` with a RISC-V bare-metal toolchain. Build the VP
first (`make smc-vp` from the repo root after `vp/configure_vp.sh`).

[source,bash]
----
cd sw/smc-vp-tests
./run_smc_vp_tests.sh smc-dma-test
----

`smc-dma-test` is a scratchpad-to-scratchpad copy through this model's
master socket on `fabric.data_accel_in`.
