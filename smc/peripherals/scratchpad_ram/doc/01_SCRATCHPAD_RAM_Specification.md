## 1. Purpose & scope

The **SMC Scratchpad RAM** is an on-chip, byte-addressable, read-write SRAM in
the System Management Controller (SMC) CPU cluster. The SMC Rocket RV64GC
cores use it as early-boot stack and data storage before external DRAM is
trained, and as a fast local scratch region thereafter.

In the RTL it is generated by the chipyard
`testchipip.soc.WithScratchpadWithECC` fragment as a TileLink SRAM with SECDED
ECC, attached to the system bus (SBUS):

```scala
new testchipip.soc.WithScratchpadWithECC(base = 0xC0040000L,
                                          size = 0x00010000L,   // 64 KiB
                                          banks = 1,
                                          partitions = 4,
                                          ecc = ECCParams(bytes = 8,
                                                          code = SECDED),
                                          busWhere = SBUS)
```

This specification defines the **externally-observable behaviour** of the
SystemC model: configuration, memory map, access semantics, byte-enable
handling, error responses, the SECDED ECC abstraction, reset, and bus
contract. It is the read-write counterpart to the Boot ROM specification.

Internal implementation choices (data layout, byte-enable loop, the ECC
error-flag map, CCI scaffolding) are documented in
[`02_SCRATCHPAD_RAM_LowLevel_Design.md`](02_SCRATCHPAD_RAM_LowLevel_Design.md).

The SystemC model is **byte-identical** to the RDL memory layout: a
contiguous `NUM_ENTRIES`-by-8-byte memory at offset 0, addressable at any
naturally-aligned `{1, 2, 4, 8}`-byte width, with per-byte write masks.

> **A note on size.** The `spm_memory.rdl` default `NUM_ENTRIES` describes a
> generic 1 MiB instance; the *generated* 1-core scratchpad is 64 KiB
> (`size = 0x10000`). The model's `size_bytes` is a CCI parameter so a single
> model serves either geometry; the default is 64 KiB to match the generated
> 1-core RTL.

## 4. Configuration parameters

The model exposes **five real `cci::cci_param<T>` declarations**. Size,
preload, and ECC-enable are immutable (changing them after elaboration would
invalidate the in-memory image); the access delay is mutable so simulations
can sweep bus speeds without rebuilding.

| Parameter           | Type          | Default      | Mutability | Notes                                                                          |
|---------------------|---------------|--------------|------------|--------------------------------------------------------------------------------|
| `size_bytes`        | `uint64_t`    | `0x10000`    | immutable  | Must be a non-zero multiple of 8 (the native 64-bit word width).               |
| `init_file`         | `std::string` | `""`         | immutable  | Optional preload image; empty = zero-fill (cold-boot state).                   |
| `init_file_format`  | `std::string` | `"auto"`     | immutable  | `"hex"`, `"bin"`, or `"auto"` (pick `bin` for `.img`/`.bin`, else `hex`).      |
| `access_delay_ns`   | `double`      | `2.0`        | mutable    | TLM `b_transport` annotated delay; pipelined read ≈ 2 cycles at 1 GHz.         |
| `ecc_enabled`       | `bool`        | `true`       | immutable  | Enables the SECDED error-injection / single-bit-scrub behaviour.               |

Override before construction via the CCI broker:

```cpp
broker.set_preset_cci_value("smc.scratchpad_ram.size_bytes",
                            cci::cci_value(uint64_t(0x10000)));
broker.set_preset_cci_value("smc.scratchpad_ram.init_file",
                            cci::cci_value(std::string("scratch.hex")));
broker.set_preset_cci_value("smc.scratchpad_ram.access_delay_ns",
                            cci::cci_value(2.0));
broker.set_preset_cci_value("smc.scratchpad_ram.ecc_enabled",
                            cci::cci_value(true));
```

The constructor still accepts a `scratchpad_ram_cfg` struct; its fields supply
**defaults** for the corresponding CCI params, so code that does not use the
CCI broker continues to work unchanged.

Fixed structural constants:

| Constant                | Value | Description                                       |
|-------------------------|-------|---------------------------------------------------|
| `WORD_BYTES`            | 8     | Native word width and ECC-protection granule (from RDL `memwidth = 64`) |
| `MAX_ACCESS_BYTES`      | 8     | Largest single `b_transport` access width accepted |

## 6. Theory of operation

The scratchpad is a contiguous byte array (`size_bytes` long, default 64 KiB)
that serves `b_transport` reads and writes verbatim. Unlike the Boot ROM,
writes **commit** — it is a true RAM.

Three properties tie the model to the RTL:

1. **Byte-masked writes.** The TileLink SRAM carries an 8-bit byte mask
   (`auto_in_a_bits_mask[7:0]`). Sub-word and partial writes are committed
   per byte; the RTL realises this with a read-modify-write so the SECDED
   code stays consistent across the whole 64-bit word. The model honours the
   TLM byte-enable array to the same effect.

2. **SECDED ECC.** Each 64-bit word is protected by a single-error-correct,
   double-error-detect code (8 ECC bits over 64 data bits → 72-bit storage in
   RTL). Single-bit errors are corrected transparently on read; double-bit
   errors are flagged on the TileLink `d` channel (`d_corrupt`). The model
   reproduces this behaviourally (see §12).

3. **Pipelined access.** The RTL read path is registered (request → SRAM →
   response), giving a ~2-cycle latency. The LT model annotates this as a
   configurable `access_delay_ns` (default 2 ns at a 1 GHz fabric clock).

## 7. Memory map

All offsets are byte offsets relative to the scratchpad base address
(`0xC0040000` in the 1-core SMC address map; the model works in local
offsets, with the bus subtracting the base).

| Range                              | Region                | Access | Size                                     |
|------------------------------------|-----------------------|--------|------------------------------------------|
| `0x00000` .. `size_bytes − 1`      | `mem_array[0..N − 1]` | R/W    | 8 B × `N` (default N = 0x2000 → 64 KiB)   |
| ≥ `size_bytes`                     | Out-of-window         | —      | `TLM_ADDRESS_ERROR_RESPONSE`              |

The default `size_bytes = 0x10000` matches the generated 1-core scratchpad
(`WithScratchpadWithECC size = 0x10000`).

## 8. Functional behaviour

### 8.1 Reads

A read at byte offset `O` with width `W ∈ {1, 2, 4, 8}` returns the byte slice
`data_[O..O+W − 1]`. Multi-byte reads honour native CPU endianness — the model
never byte-swaps.

| Property              | Behaviour                                  |
|-----------------------|--------------------------------------------|
| Alignment             | Naturally aligned to `W` bytes              |
| Width range           | `W ∈ {1, 2, 4, 8}`                          |
| Byte-enables          | Honoured: only enabled bytes are returned   |
| Response status       | `TLM_OK_RESPONSE` on success                |
| Annotated delay       | `+= access_delay_ns × ns`                   |
| Side effects          | A correctable ECC error on a covered word is scrubbed (see §12) |

### 8.2 Writes

A write at byte offset `O` with width `W` and in-range `O + W ≤ size_bytes`:

| Property              | Behaviour                                  |
|-----------------------|--------------------------------------------|
| Effect on `data_`     | Enabled bytes committed; disabled bytes unchanged |
| Byte-enables          | Honoured: per-byte write mask               |
| Response status       | `TLM_OK_RESPONSE`                           |
| Annotated delay       | `+= access_delay_ns × ns`                   |
| ECC                   | Touched words are re-encoded (any injected error on them is cleared) |
| Subsequent read       | Returns the just-written value              |

### 8.3 Preload contract

At construction time, if `init_file` is non-empty, the file is opened and
decoded according to the resolved format (see §13). The decoded bytes are
stored starting at offset 0; the remainder is left zero. If `init_file` is
empty the entire RAM is zero-initialised — the usual cold-boot state.

Preload errors (file not found, unreadable, malformed) are reported with
`SC_REPORT_FATAL` at elaboration time, so an integration mistake fails fast.

### 8.4 Reset behaviour

Reset is a **structural no-op for the array**: real SRAM retains its contents
across a logical reset, and the RTL only resets the TileLink bus pipeline
registers (`d_full` / `r_full`). The `reset_proc` SC_METHOD is registered for
IP-suite symmetry — every other SMC IP exposes a `rst_n_i`.

---

## 9. Reset behaviour

| Signal      | Polarity   | Edge          | Effect on RAM state |
|-------------|------------|---------------|---------------------|
| `rst_n_i`   | active-low | level-low     | **None** (SRAM retains contents) |

A wired-low `rst_n_i` does not stall the bus interface — reads and writes
continue to be served throughout the reset window in the LT model.

## 10. Bus interface (TLM-2.0 / TileLink-style)

### 10.1 Socket type

```cpp
tlm_utils::simple_target_socket<scratchpad_ram> reg_socket;
```

Registered callbacks:

```cpp
reg_socket.register_b_transport  (this, &scratchpad_ram::b_transport);
reg_socket.register_transport_dbg(this, &scratchpad_ram::transport_dbg);
```

DMI is **deliberately not registered**. A RAM is a strong DMI candidate, but a
DMI write would bypass the SECDED re-encode path, so we keep it un-granted for
parity with the other SMC IPs (see `02_SCRATCHPAD_RAM_LowLevel_Design.md §16`
for the future-work item).

### 10.2 Transaction contract

| Field             | Required value                            | Notes |
|-------------------|-------------------------------------------|-------|
| `command`         | `TLM_READ_COMMAND` / `TLM_WRITE_COMMAND`  | `TLM_IGNORE_COMMAND` → `TLM_COMMAND_ERROR_RESPONSE` |
| `address`         | aligned to `data_length`, `< size_bytes`  | Otherwise error (see §11) |
| `data_length`     | `1`, `2`, `4`, or `8`                     | Otherwise `TLM_BURST_ERROR_RESPONSE` |
| `streaming_width` | == `data_length`                          | Otherwise `TLM_BURST_ERROR_RESPONSE` |
| `byte_enable_ptr` | optional                                  | When set, selects which bytes are read/written (per-byte mask) |
| `dmi_allowed`     | (cleared on every transaction)            | DMI never granted |

### 10.3 Timing annotation

`b_transport` adds `sc_time(access_delay_ns_p_.get_value(), SC_NS)` to the
supplied `delay`. The model re-reads the CCI param on every transaction, so a
broker-driven mutation takes effect on the next access. `transport_dbg` adds
nothing — debug accesses are zero-time by TLM-2.0 convention.

### 10.4 `transport_dbg`

Side-effect-free for timing, but **read-write** like `b_transport` (debug
writes commit). Debug accesses **bypass ECC** (a debugger sees raw memory). On
validation error `transport_dbg` returns 0; on success it returns the number
of bytes transferred.

## 11. Error handling

| Condition                                       | Detection                | Response                            |
|-------------------------------------------------|--------------------------|-------------------------------------|
| `data_length` ∉ `{1, 2, 4, 8}`                  | `b_transport` precheck   | `TLM_BURST_ERROR_RESPONSE`          |
| Address not naturally aligned to `data_length`  | `b_transport` precheck   | `TLM_BURST_ERROR_RESPONSE`          |
| `streaming_width ≠ data_length`                 | `b_transport` precheck   | `TLM_BURST_ERROR_RESPONSE`          |
| `address ≥ size_bytes` or `address + len > size_bytes` | `b_transport` window check | `TLM_ADDRESS_ERROR_RESPONSE`     |
| Unsupported command (`TLM_IGNORE_COMMAND`)      | `b_transport` switch     | `TLM_COMMAND_ERROR_RESPONSE`        |
| Read of a word with an uncorrectable ECC error  | `b_transport` ECC check  | `TLM_GENERIC_ERROR_RESPONSE`        |
| Construction with `size_bytes = 0` or non-multiple of 8 | Constructor      | `SC_REPORT_FATAL` at elaboration    |
| Construction with `access_delay_ns < 0`         | Constructor              | `SC_REPORT_FATAL` at elaboration    |
| Preload file missing / unreadable / empty       | `load_preload()`         | `SC_REPORT_FATAL` at elaboration    |
| Malformed hex line                              | `parse_hex_line()`       | `SC_REPORT_FATAL` (file + line no.) |
| Hex preload overflow with **non-zero** data     | `load_preload()`         | `SC_REPORT_FATAL`                   |
| Hex preload overflow with **all-zero** tail     | `load_preload()`         | Tolerated (truncated silently)      |

`SC_REPORT_FATAL` is reserved for elaboration-time misconfiguration; runtime
failures use TLM response codes so the surrounding fabric and test bench see
deterministic bus-level errors.

## 12. ECC (SECDED) model

The RTL scratchpad protects each 64-bit word with a SECDED code. A
bit-accurate ECC model is out of scope for an LT functional model; instead the
model provides a **behavioural abstraction** controlled by the `ecc_enabled`
CCI parameter and a debug error-injection API.

| API / event                                  | Behaviour |
|----------------------------------------------|-----------|
| `dbg_inject_ecc_error(off, correctable=true)`  | Marks the covering word as having a single-bit error. |
| Read covering a correctable word             | Succeeds; data returned intact; the flag is **scrubbed** (matches SECDED auto-correct on access). |
| `dbg_inject_ecc_error(off, correctable=false)` | Marks the covering word as having an uncorrectable (double-bit) error. |
| Read covering an uncorrectable word          | `TLM_GENERIC_ERROR_RESPONSE` (LT analogue of TileLink `d_corrupt`). |
| Any write to a word                          | Re-encodes the word; clears its error flag. |
| `dbg_clear_ecc_errors()`                     | Drops all injected error flags. |
| `ecc_enabled = false`                        | Injection is a no-op; the model behaves as a plain RAM. |

With no injected errors (the default) the model behaves as a plain RAM. The
error flags are stored sparsely (a hash map keyed by word offset), so there is
no per-word memory or time overhead in the common case.

## 13. Preload formats

A preload is **optional** for a scratchpad (it normally cold-boots to zero),
but is supported for deterministic test fixtures. The format is identical to
the Boot ROM's preload pipeline.

### 13.1 Hex format (`init_file_format = "hex"`)

Plain text, one 64-bit word per line, big-endian ASCII hex (most significant
nibble first). Compatible with `xxd -r -p` round-tripping. Blank lines and
`#`-prefixed comments are ignored; an optional `0x` / `0X` prefix is accepted.
Each line is stored little-endian at the next consecutive 8-byte slot.

### 13.2 Binary format (`init_file_format = "bin"`)

Raw binary, dumped to disk as a contiguous byte stream. Each 8 bytes on disk
form one 64-bit word, stored at the matching offset without any swap.

### 13.3 `auto` resolution

The default `init_file_format = "auto"` picks `bin` if the filename ends in
`.img` or `.bin` (case-insensitive), and `hex` otherwise. Any other value
falls back to the same auto-detection rule.

### 13.4 Zero-padding rules

| File size      | Preload result                                                |
|----------------|---------------------------------------------------------------|
| 0 bytes        | `SC_REPORT_FATAL` (empty preload is treated as an error)      |
| `< size_bytes` | Loaded into `data_[0..N-1]`; the remainder is zero            |
| `= size_bytes` | Exact fit                                                     |
| `> size_bytes` (hex) | Tolerated **iff** every overflow word is zero; non-zero overflow word → `SC_REPORT_FATAL` |
| `> size_bytes` (bin) | Truncated silently                                      |

## 14. Compliance matrix

| Claim | Source                                  | Statement                                                  | Model behaviour |
|-------|-----------------------------------------|------------------------------------------------------------|-----------------|
| —     | RDL `sw=rw, hw=rw`                       | RAM is software read-write                                 | Reads return stored data; writes commit |
| —     | RDL `memwidth = 64`                      | 64-bit native word width                                   | Default `size_bytes` is `NUM_ENTRIES × 8`; 8-byte access is the maximum |
| —     | RTL `auto_in_a_bits_mask[7:0]`          | Per-byte write mask (sub-word writes via RMW)              | Byte-enables honoured on read and write |
| —     | RTL SECDED ECC (`d_corrupt`)            | Single-bit corrected, double-bit flagged                  | Behavioural SECDED model (§12) |
| —     | RTL pipelined read                       | ~2-cycle read latency                                      | `access_delay_ns` default 2 ns |
| —     | RTL reset                                | SRAM array not cleared by reset                            | `reset_proc` is a no-op; contents retained |
| —     | SMC IP convention                        | All SMC IPs expose `rst_n_i`                               | `rst_n_i` registered as `SC_METHOD` |

### 14.1 Documented deviations

| Item                                  | Reason                                                                |
|---------------------------------------|-----------------------------------------------------------------------|
| Atomic memory operations (AMOs)       | The TileLink SRAM supports arithmetic/logical atomics via its RMW ALU; the LT model treats writes as plain stores. Future work. |
| Bit-accurate SECDED                   | Modelled behaviourally (injection API) rather than a true Hamming code. |
| DMI fast-path                         | Un-granted: a DMI write would bypass the SECDED re-encode. Future work. |

### 14.2 Unmodelled features

| Item                                  | Reason                                                                |
|---------------------------------------|-----------------------------------------------------------------------|
| Approximately-Timed (AT) protocol     | LT model is sufficient for SW bring-up.                              |
| Per-bank / per-partition timing       | The RTL splits the array into 4 partitions; the model is a single flat array (functionally identical). |
| ECC error counters / interrupts       | `notifyErrors = false` in the RTL config; errors are reported on the bus only. |

## 16. Glossary

- **Scratchpad RAM** — A small, on-chip, byte-addressable read-write memory
  used by a processor for fast local storage.
- **SECDED** — Single-Error-Correct, Double-Error-Detect ECC code; corrects
  one bit error and detects (but cannot correct) two.
- **Byte-enable** — A per-byte write mask; lets a transaction update a subset
  of the bytes in a word.
- **RMW (Read-Modify-Write)** — How the RTL applies a sub-word write under an
  ECC code: read the word, merge the new bytes, re-encode ECC, write back.
- **TileLink** — The on-chip bus protocol used by the Rocket/chipyard CPU
  cluster; the scratchpad is a TileLink SRAM target.
- **DMI** — TLM-2.0 Direct Memory Interface; a back-door pointer for fast
  access (not granted by this model).
- **LT (Loosely-Timed)** — TLM-2.0 modelling style: `b_transport`, optional
  DMI, coarse `sc_time` annotations.
- **RDL** — SystemRDL register-description language; the authoritative
  scratchpad declaration lives in `spm_memory.rdl`.
- **CCI** — SystemC Configuration, Control and Inspection (Accellera
  cci-1.0.0). Provides the `cci_param<T>` interface used here.
- **SMC** — System Management Controller; the RV64GC management complex whose
  IP library this model belongs to.
- **SC_REPORT_FATAL** — SystemC's mechanism for reporting an unrecoverable
  configuration error during elaboration.
