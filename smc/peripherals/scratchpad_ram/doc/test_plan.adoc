[[scratchpad-ram-test-plan]]
===== Test Plan

====== Standalone bench

`scratchpad_ram_tb` and `scratchpad_ram_neg_tb` (`test/`). The primary
bench covers read/write, byte-enables, reset retention, and ECC
injection. The negative bench probes constructor/preload fatals.

Success: both benches print `ALL TESTS PASSED`; CTest reports 2/2;
`--asan` produces no `asan.log.*`. Existing coverage of
`src/scratchpad_ram.cpp` is ~98% line.

How to run (from `smc/peripherals/scratchpad_ram`):

[source,bash]
----
./run_tests.sh              # Release build + run both benches
./run_tests.sh --ctest
./run_tests.sh --asan
./run_tests.sh --coverage   # isolated build_cov/; do not combine with --asan
./run_tests.sh --clean

cd smc
./run_all_smc_tests.sh scratchpad_ram
----

`run_tests.sh` probes `SYSTEMC_HOME` / `CCI_HOME`.

====== Platform firmware tests

There is no `smc-scratch-test` in `sw/smc-vp-tests/`. Scratchpad traffic
on `smc-vp` is covered by `smc-dma-test` and `smc-memory-zeroer-test`.

[source,bash]
----
cd sw/smc-vp-tests
./run_smc_vp_tests.sh smc-dma-test
./run_smc_vp_tests.sh smc-memory-zeroer-test
----
